# Repository Working Agreement

## Authority and evidence

- Read `README.md` and `.github/CONTRIBUTING.md` before editing.
- Accepted Nexa Product, Domain, architecture and design decisions remain the
  semantic authority. This repository is an academic report and evidence
  projection; it does not redefine Product authority.
- Preserve the distinction between planned, designed, implemented, verified,
  accepted and production-ready. Never describe TARGET as implemented.
- State only what the cited source supports. Never invent interviews,
  screenshots, tests, metrics, Sprint completion, acceptance or deployment.
- Preserve citation, source, link and asset integrity. Keep private interview
  data, local paths, secrets and temporary evidence out of the repository.

## Report quality

- Keep submitted prose polished, publication-ready and neutral.
- Do not add internal evaluator labels, prompt residue, orchestration language,
  communication addressed to a person, obvious placeholders or AI attribution.
- Academic rubric compliance and academic truth have equal importance. Resolve
  rubric ambiguity outside submitted prose rather than fabricating evidence.
- Do not mix repository governance with chapter content. A root AGENTS change
  uses a truthful governance scope; it is not a chapter change.
- Actual chapter-content commits use the repository convention, for example
  `docs(ch2): <description>`. Do not use a chapter scope for this file.

## Repository state

- Inspect the actual branch, worktree, remote metadata and working tree before
  editing.
- Propose normal work against the active integration branch described by the
  contribution policy. Fetch remote metadata before creating new work when
  permitted; do not merge fetched changes into a user's working branch.
- Preserve unrelated local work and use an isolated worktree when the checkout
  is dirty.

## Evidence and SCM

- Run and report only the narrowest relevant checks. Do not generate a PDF or
  alter report assets, chapters, Sprint evidence or semantic projections for a
  governance-only change.
- Follow `.github/CONTRIBUTING.md` for signed history, Conventional Commits,
  review and export boundaries.
- Do not force-push, rewrite shared history, create fake commits, invent
  contributors, merge automatically, create releases or create tags.
- Repository-facing artifacts must contain no internal orchestration residue,
  temporary placeholders or unsupported completion claims.

## Final handoff

Report the factual result, files changed, checks actually executed, commit and
push state, remaining risks, open decisions and unverified evidence. Do not
claim academic, Product or release acceptance from this governance change.
