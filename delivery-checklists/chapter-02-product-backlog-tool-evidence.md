# Chapter II — Product Backlog Tool Evidence Guide

## Purpose

Use this internal guide when the academic Product Backlog must be synchronized
with an external planning tool. The Markdown backlog remains the readable source
for the report; tool evidence is additional human evidence and is not exported
as a chapter.

## Source inventory

- [ ] Create or synchronize all 97 entries.
- [ ] Preserve 73 `MOB-US`, 6 `LAND-US`, 12 `TS-MOB` and 6 `SPIKE` entries.
- [ ] Keep each identifier unique.
- [ ] Preserve the five report columns: `# Orden`, `User Story Id`, `Título`, `Story Points`, `Sprint`.
- [ ] Preserve the global order from `2.4.3-product-backlog.md` unless new accepted Product evidence justifies a documented change.

## Priority and planning checks

- [ ] Business value remains the primary ordering factor.
- [ ] Risk and uncertainty are visible where an early Spike genuinely reduces risk.
- [ ] Dependencies explain technical placement without making every prerequisite the highest-value item.
- [ ] Landing entries remain in Sprint 1.
- [ ] Story Points remain relative estimates of effort, complexity and uncertainty.
- [ ] Sprint remains a plan, not a substitute for Product priority.

## Evidence capture

- [ ] Capture a readable view of the complete backlog or a set of non-ambiguous views.
- [ ] Keep IDs, titles, points, Sprint and order legible at report scale.
- [ ] Do not expose private project, account, token or workspace information.
- [ ] Record the real public URL if the chosen platform permits public access.
- [ ] If no public URL is available, preserve the actual exported or captured evidence and state that limitation.

## Report insertion

- [ ] Insert only the real screenshot or export in the approved Chapter II asset path.
- [ ] Insert only the real public URL, never a placeholder or guessed link.
- [ ] Validate the local Markdown link.
- [ ] Re-run the Chapter II validators.
- [ ] Review readability in the PDF.
