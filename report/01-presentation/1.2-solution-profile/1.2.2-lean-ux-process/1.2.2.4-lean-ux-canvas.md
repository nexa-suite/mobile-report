# 1.2.2.4 Lean UX Canvas

El siguiente Canvas reúne las ocho conversaciones de Lean UX. Su contenido es
una declaración inicial de supuestos y debe actualizarse cuando las entrevistas
y los experimentos aporten nueva evidencia.

| Box | Contenido aplicado a Nexa |
| --- | --- |
| **1. Business Problem** | La distribución B2B coordina pedidos y entregas con información fragmentada entre ventas, operación, almacén, despacho, ruta y compradores. La brecha principal es la falta de continuidad entre la intención de compra y la ejecución operativa cuando el trabajo ocurre en distintos contextos. |
| **2. Business Outcomes** | Reducir la reconstrucción manual de solicitudes; aumentar la continuidad de tareas operativas; reducir consultas repetitivas de compradores; y aprender qué comportamientos justifican ampliar o reducir el alcance. Estos outcomes se observarán mediante tiempos, pasos repetidos, consultas de apoyo, tareas recuperadas tras desconexión y evidencias correctamente asociadas. |
| **3. Users** | Como hipótesis inicial: personas comerciales; personal de almacén y despacho; conductores o repartidores; compradores B2B; y Business Operations Manager como actor móvil secundario. La segmentación final se presenta en 1.3 y permanece pendiente de validación. |
| **4. User Outcomes and Benefits** | Las personas buscan registrar y continuar tareas sin reconstruir información; preparar y entregar con evidencias; recuperar trabajo autorizado tras una desconexión; y comprar o consultar pedidos con menor incertidumbre. El beneficio esperado es continuidad, claridad, autonomía y menor retrabajo. |
| **5. Solutions** | Experiencias Operations Mobile y Buyer Mobile; almacenamiento local selectivo con sincronización explícita; acceso controlado a cámara, escaneo y ubicación; integración con RESTful API interno; servicio externo de terceros; y un feature de aprendizaje autónomo. Cada solución debe probarse de manera independiente o con un experimento acotado. |
| **6. Hypotheses** | H1 a H7 de la sección anterior. Cada hipótesis relaciona un outcome, un usuario, un beneficio y una sola solución principal, con criterio de éxito y experimento inicial. |
| **7. Learning** | Primero necesitamos aprender si los actores candidatos consideran valiosa la continuidad móvil en sus tareas reales y si pueden distinguir con claridad entre información local pendiente y estado confirmado por el servidor. También debemos identificar qué riesgo de valor invalida cada hipótesis. |
| **8. MVPs and Experiments** | Prototipos navegables, pruebas en dispositivo físico, escenarios con conectividad interrumpida, un spike de integración RESTful, una prueba acotada del servicio externo y un spike del feature de aprendizaje autónomo. El MVP se define como el menor trabajo que permita aprender lo siguiente, no como una versión completa del producto. |

El Canvas no afirma que las aplicaciones, integraciones o segmentos estén
validados. Sirve para ordenar el aprendizaje antes de convertir las ideas en
requisitos y trabajo de implementación.
