## 2.2 Interviews

La investigación con usuarios móviles todavía está incompleta. Esta sección
conserva una guía para los tres segmentos, dos entrevistas Buyer B2B válidas y
el análisis de su muestra real (`n = 2`). Las entrevistas de otros perfiles se
excluyen por no ser útiles para los segmentos móviles definidos. La evidencia de
investigación se mantiene separada de las propuestas de diseño.

---

### 2.2.1 Interview Design

#### Propósito y límite de esta guía

Esta guía recoge evidencia sobre cómo se realiza hoy el trabajo móvil o cercano
al punto físico de operación. Primero solicita un caso reciente y verificable;
después indaga herramientas, decisiones, excepciones y condiciones de uso. No
presenta la solución de Nexa como si fuera un hecho ni convierte una entrevista
en aceptación de producto.

La investigación sigue tres segmentos de planificación. Son categorías de
investigación, no User Personas validadas ni Bounded Contexts.

| Segmento | Participantes directos buscados | Cobertura requerida | Pregunta de aprendizaje |
| --- | --- | --- | --- |
| `MOB-SEG-01 — Warehouse & Dispatch Operations` | `Warehouse Operator` y `Dispatch Coordinator` que ejecuten o coordinen tareas reales de recepción, preparación, salida o handoff. | 3–5 entrevistas; debe haber representación de ambos roles y registrarse cuántas corresponden a cada uno. | **H1:** ¿la transición preparación → readiness → handoff genera reconstrucción, aclaraciones u omisiones relevantes? |
| `MOB-SEG-02 — Driver Delivery Execution` | `Driver` o `Delivery Operator` que haya realizado entregas recientes. | 3–5 entrevistas directas. | **H2:** ¿la atribución del Delivery Attempt, sus incidencias y su evidencia es una fricción material? |
| `MOB-SEG-03 — B2B Buyers` | `Customer Buyer` o responsable que participe efectivamente en recepción, verificación o discrepancias B2B. | 3–5 entrevistas directas. | **H3:** ¿la recepción y la comunicación de discrepancias requieren un recorrido Mobile acotado? |

Una persona sólo cuenta para un segmento cuando describe las tareas de ese
segmento. Un título laboral, una relación comercial genérica o una entrevista
de otro rol puede conservarse como contexto, pero no se reclasifica para
completar la muestra.

#### Protocolo de sesión

1. Explicar el propósito académico, el uso de los datos y pedir consentimiento
   antes de grabar, capturar o publicar evidencia.
2. Pedir un caso reciente completo antes de mostrar cualquier idea de Nexa.
3. Separar lo que la persona hizo, lo que interpreta y lo que propone para el
   futuro.
4. Cerrar con una síntesis verificable por la participante o el participante.
5. Registrar únicamente los datos personales necesarios y marcar como
   `NO DECLARADO` aquello que no fue aportado; nunca inferirlo de nombre,
   imagen o contexto.

La apertura sugerida es:

> Gracias por tu tiempo. Estamos estudiando cómo se prepara, entrega o recibe
> hoy un pedido B2B. No evaluamos tu desempeño ni el de tu empresa. Nos interesa
> un caso reciente, las herramientas que usaste y los problemas que aparecieron.
> ¿Autorizas el registro de esta conversación sólo para el análisis académico
> descrito?

#### Preguntas principales para `MOB-SEG-01 — Warehouse & Dispatch Operations`

La guía se aplica según el rol de la persona entrevistada. Las preguntas de
recepción, picking y condición del producto se formulan a quienes realizan esas
tareas; las de salida y handoff se aplican a quienes coordinan el despacho.

| Tema | Preguntas principales |
| :--- | :--- |
| Rol y contexto | ¿Qué responsabilidad cumples en recepción, almacén, preparación o despacho?, ¿qué ocurre antes y después de tu tarea? |
| Caso reciente | Cuéntame el último pedido o movimiento que atendiste desde que llegó al almacén hasta que quedó listo para su salida. |
| Identificación y condición | ¿Cómo reconoces producto, lote, vencimiento, cantidad y condición?, ¿qué sucede cuando el código, la etiqueta o lo físico no coinciden? |
| Inventario y preparación | ¿Cómo confirmas disponibilidad?, ¿cómo eliges la cantidad o lote correcto?, ¿qué pasos siguen quienes preparan el pedido? |
| Salida y handoff | ¿Cómo sabes que un pedido está listo para salir?, ¿quién recibe la responsabilidad siguiente y qué evidencia queda? |
| Excepciones | ¿Qué haces ante faltantes, merma, lote no conforme, producto dañado, datos incompletos o un cambio de última hora? |
| Herramientas y entorno | ¿Qué usas hoy: teléfono, ERP, hojas de cálculo, mensajería, etiquetas o documentos?, ¿qué cambia cuando manipulas mercadería o te desplazas dentro de la operación? |
| Adopción | Si pudieras simplificar una parte de este flujo, ¿cuál sería?, ¿qué haría que una herramienta se use todos los días? |

#### Preguntas principales para `MOB-SEG-02 — Driver Delivery Execution`

| Tema | Preguntas principales |
| :--- | :--- |
| Inicio de la jornada | ¿Cómo recibes una entrega asignada y qué revisas antes de iniciar la ruta? |
| Condiciones de uso | ¿Cuándo usas el teléfono durante la ruta?, ¿qué limita tu atención, batería, conectividad o visibilidad de la pantalla? |
| Entrega | Cuéntame el último intento completo: llegada, contacto, entrega, rechazo o reprogramación. |
| Incidencias | ¿Cómo registras una dirección incorrecta, ausencia del comprador, faltante, daño o rechazo? |
| Evidencia | ¿Qué foto, código, firma, lectura o nota necesitas conservar para demostrar lo ocurrido? |
| Conservación | ¿Qué evidencia de conservación debe acompañar una entrega de productos sensibles y cómo se registra actualmente? |
| Recuperación | ¿Qué haces si se pierde la conexión, falla la cámara, el escáner o la aplicación? |
| Privacidad y soporte | ¿Qué datos de comprador o entrega no debería ver otro rol?, ¿cuándo necesitas llamar a coordinación? |

#### Preguntas principales para `MOB-SEG-03 — B2B Buyers`

| Tema | Preguntas principales |
| :--- | :--- |
| Negocio y rol | ¿Qué negocio atiendes y qué responsabilidad tienes al recibir o verificar pedidos de proveedores? |
| Pedido esperado | ¿Cómo sabes qué entrega debe llegar, qué productos esperas y a quién corresponde recibirlos? |
| Aviso y llegada | ¿Cómo te enteras de que una entrega está en camino o ya llegó?, ¿qué información debes confirmar antes de atenderla? |
| Recepción | ¿Cómo compruebas la identidad de la entrega, las cantidades y el estado de los productos recibidos? |
| Documentos y pagos | ¿Cómo consultas documentos, saldos o comprobantes vinculados con una compra o recepción? |
| Discrepancias | Cuéntame el último faltante, daño, diferencia o cambio de entrega y cómo se resolvió. |
| Canales y dispositivos | ¿Cuándo usas llamadas, WhatsApp, Excel, una aplicación u otro canal?, ¿desde qué dispositivo? |
| Confianza y soporte | ¿Qué información te daría confianza para usar una herramienta digital?, ¿en qué casos preferirías apoyo humano? |

#### Registro y lectura de evidencia

Cada ficha debe incluir, con autorización: rol y tareas observadas, contexto de
la sesión, dispositivos/canales declarados, URL o referencia de la evidencia,
timing, duración, resumen descriptivo y evaluación de ajuste al segmento.
Información demográfica o personal no necesaria se omite o se declara como no
disponible.

| Nivel | Significado |
| --- | --- |
| Observación | Hecho, herramienta, dificultad o secuencia narrada por una persona. |
| Interpretación | Patrón identificado dentro de una muestra del mismo segmento; siempre declara su denominador. |
| Propuesta | Pregunta de seguimiento o implicación de diseño; no es un hallazgo validado. |

Antes de formular porcentajes, User Personas o métricas se comprobará la
cobertura mínima de cada segmento. Una muestra incompleta se presenta con su
alcance limitado; no se rellena con filas reservadas ni se extrapola desde otro
segmento.
