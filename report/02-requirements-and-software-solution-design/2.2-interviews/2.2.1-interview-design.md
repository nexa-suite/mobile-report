# 2.2.1 Interview Design

Este documento define la campaña de needfinding para las superficies móviles de
Nexa. El corte actual no contiene entrevistas del curso verificadas; por ello,
el plan no presenta preguntas como respuestas ni convierte material histórico en
evidencia actual.

## Segmentos y obligación de muestra

| Segmento | Actores de interés | Alcance a investigar | Muestra requerida | Estado |
| :--- | :--- | :--- | :---: | :--- |
| S1 — Field & Warehouse Operations | Sales Representative (V2+), Warehouse Operator, Dispatch Coordinator | Tareas de almacén y despacho V1; preguntas de ventas en campo como alcance diferido | 3–5 | RESEARCH_PENDING |
| S2 — Delivery Workforce | Driver / Delivery Operator | Inicio de ruta, intento de entrega, evidencia, conectividad, privacidad y seguridad | 3–5 | RESEARCH_PENDING |
| S3 — B2B Buyers | Customer Buyer | Catálogo, solicitud, entrega, recepción, discrepancia y necesidades financieras | 3–5 | RESEARCH_PENDING |

Las entrevistas históricas de Commercial Coordination y B2B Buyer se registran
en el [ledger de reutilización](../../../delivery-checklists/legacy-reuse-ledger.md)
como candidatas condicionadas. Las entrevistas históricas de Operations /
Account Owner no cuentan por defecto para el nuevo S2.

## Objetivos de investigación

1. Describir el trabajo físico y las decisiones que preceden a una recepción,
   identificación de lote, picking, packing, staging y despacho.
2. Entender cómo un conductor inicia, ejecuta y cierra un intento de entrega,
   incluyendo entrega parcial, rechazo, prueba de entrega y handoff al comprador.
3. Identificar condiciones de conectividad, batería, ergonomía, seguridad,
   permisos de cámara/scanner, privacidad y recuperación ante errores.
4. Comparar la información que necesita cada actor con la evidencia que debe
   quedar registrada, sin asumir que un prototipo o una historia ya fue aceptada.
5. Contrastar las historias V1 con el trabajo real y documentar qué se confirma,
   qué se modifica y qué permanece abierto.

## Estrategia de participantes

### Inclusión

- Persona con experiencia reciente en una de las actividades del segmento.
- Participación voluntaria y consentimiento para registrar la sesión.
- Capacidad para describir un caso real, una excepción y el artefacto utilizado.
- Para S2, preferencia por roles de almacén, despacho, reparto o coordinación de
  entrega que observen el flujo físico, no sólo una función administrativa.

### Exclusión

- Personas sin contacto con el proceso investigado.
- Miembros del equipo que se presenten como sustitutos del usuario final.
- Entrevistas sin autorización para identificar segmento, rol, fecha y evidencia.
- Registros que no permitan distinguir una opinión, una observación y una
  decisión interna del equipo.

La campaña no inventa nombres, edades, cargos, citas, porcentajes, pain points,
personas ni requisitos. Una persona candidata no se convierte en participante
hasta que exista un registro revisado.

## Protocolo de sesión

1. Presentar propósito, duración, uso académico y límites de privacidad.
2. Solicitar consentimiento explícito para grabación y uso de capturas.
3. Registrar contexto de trabajo, rol, dispositivos, conectividad y frecuencia
   sólo con los datos que la persona autorice.
4. Pedir que describa el último caso real y, si es posible, que muestre el
   flujo o artefacto sin exponer información confidencial de terceros.
5. Explorar el caso normal, una excepción, un handoff y una recuperación.
6. Separar lo que la persona hace hoy de lo que desearía que hiciera Nexa.
7. Cerrar con una pregunta de adopción, riesgos y oportunidad para aclarar el
   registro.
8. Guardar el video, captura, consentimiento, notas y enlace individual en un
   registro con identificador estable.

## Guía de preguntas

| Tema | Preguntas abiertas |
| :--- | :--- |
| Contexto | ¿Qué responsabilidad cumples y qué ocurre antes y después de esta tarea? |
| Frecuencia | ¿Con qué frecuencia realizas esta actividad y cuándo se vuelve urgente? |
| Flujo normal | Cuéntame el último caso completo, desde el inicio hasta el cierre. |
| Excepciones | ¿Qué ocurre cuando falta stock, el lote no coincide, el comprador rechaza o el dato está incompleto? |
| Handoffs | ¿Quién entrega información o bienes a quién y cómo sabes que la transferencia ocurrió? |
| Dispositivos | ¿Qué dispositivo usas en cada etapa? ¿Qué haces cuando la cámara, scanner o batería falla? |
| Conectividad | ¿Dónde se pierde la conexión? ¿Qué información puedes consultar o registrar sin ella? |
| Evidencia | ¿Qué dato, foto, lectura, código, firma o comprobante necesitas conservar? |
| Seguridad | ¿Qué información no debería ver otro rol, tenant, conductor o comprador? |
| Ergonomía | ¿Qué postura, ambiente, temperatura, iluminación o movimiento afecta la tarea? |
| Adopción | ¿Qué haría que una herramienta se use todos los días y qué la haría fracasar? |
| Integraciones | ¿Qué sistema, servicio o recurso del dispositivo interviene hoy y qué problema causa? |
| Resultado | ¿Cómo sabes que la tarea terminó correctamente y qué haces si no puedes confirmarlo? |
| Priorización | Si sólo pudieras mejorar una parte del flujo, ¿cuál sería y por qué? |
| Cierre | ¿Qué no te pregunté y sería importante para diseñar una herramienta segura? |

## Evidencia mínima por registro

Cada entrevista futura debe contener nombre y apellido autorizado, edad, distrito,
rol, segmento, dispositivos, fecha, duración, inicio y fin en el video,
consentimiento, captura, enlace individual, enlace consolidado, preguntas
aplicadas, resumen descriptivo y curso de origen. El registro debe conservar la
etiqueta original si el material se reutiliza.

## Análisis previsto

Se codificarán tareas, frecuencia, severidad del error, excepciones, handoffs,
conectividad, evidencia, privacidad, ergonomía y adopción. Las tablas de
frecuencias y porcentajes se calcularán por segmento sólo después de cerrar la
muestra y revisar cada registro; no se proyectarán desde la guía ni desde la
existencia de una historia.
