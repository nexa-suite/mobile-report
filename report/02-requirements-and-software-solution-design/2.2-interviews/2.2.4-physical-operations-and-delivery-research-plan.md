# 2.2.4 Physical Operations and Delivery Research Plan

## Purpose

Este plan prepara la investigación nueva que exige el alcance móvil para el
trabajo físico y la entrega. No es un registro de entrevistas realizadas ni
una fuente para afirmar que una historia fue validada.

La separación vigente es:

- **S1 — Field & Warehouse Operations:** Warehouse Operator y Dispatch
  Coordinator para el alcance V1; Sales Representative queda diferido.
- **S2 — Delivery Workforce:** Driver / Delivery Operator.
- **S3 — B2B Buyers:** Customer Buyer.

Las entrevistas históricas con el rótulo `S2 — Operations / Account Owner` se
mantienen fuera de la muestra nueva salvo decisión humana explícita.

La literatura y las guías institucionales se usarán como contexto secundario,
no como sustituto de entrevistas: [D1] resume líneas de investigación y vacíos
de factores humanos, [D2] distingue tracking de producto y monitoreo de vida
útil, y la [síntesis secundaria de S2](./2.2.5-secondary-research-physical-operations-and-delivery.md)
organiza preguntas sobre trazabilidad, temperatura y ergonomía. Ninguna fuente
confirma una regla de negocio de Nexa ni autoriza live tracking, IoT o una
capacidad offline.

## Preguntas de investigación

### Recepción y almacén

- ¿Cómo se recibe una carga y cómo se identifica el Product o SKU?
- ¿Qué datos de lote, vencimiento, cantidad y condición se comprueban?
- ¿Cómo se decide FEFO y quién puede corregir una discrepancia física?
- ¿Cómo se realiza picking, packing y staging antes del despacho?
- ¿Qué ocurre si la cantidad, el lote, el documento o la temperatura no coincide?
- ¿Qué lectura o evidencia se necesita para liberar, retener, devolver o escalar
  un producto?

### Despacho y transferencia

- ¿Qué condiciones hacen que una entrega esté lista para despacho?
- ¿Cómo se asigna el conductor y cómo se comprueba que recibe los bienes
  correctos?
- ¿Qué identifica la transferencia almacén–conductor y cómo se conserva su
  evidencia?
- ¿Qué significa que los bienes dejaron el control del almacén?
- ¿Qué datos pueden ver almacén, coordinación, conductor y comprador sin
  romper el aislamiento del Tenant?

### Entrega y recepción

- ¿Cómo inicia el conductor un Delivery Attempt?
- ¿Qué ocurre en una entrega completa, parcial, rechazada o fallida?
- ¿Qué es Proof of Delivery en el proceso real y qué requisitos tiene?
- ¿Cómo se entrega y verifica el handoff con el Buyer?
- ¿Cómo se distinguen Driver Outcome, Buyer Receipt y Discrepancy?
- ¿Qué evidencia se conserva cuando el comprador recibe una cantidad distinta?

### Condiciones de uso

- ¿Dónde se pierde la conectividad y qué tarea se interrumpe?
- ¿Qué información puede consultarse, redactarse o reintentarse sin conexión?
- ¿Qué riesgos hay de batería, iluminación, guantes, frío, movimiento, ruido o
  postura?
- ¿Qué permiso de cámara, scanner, notificaciones o ubicación se solicita y
  cómo se continúa si la persona lo deniega?
- ¿Qué dato personal, ubicación o imagen no debe conservarse?
- ¿Qué haría que una herramienta se adopte o se abandone?

## Participantes candidatos

La muestra será de **3–5 participantes por segmento**. Son roles candidatos,
no participantes confirmados:

| Segmento | Roles candidatos | Motivo de selección |
| :--- | :--- | :--- |
| S1 | Warehouse Operator; Inventory Operator; Dispatch Coordinator | Cubrir recepción, lote, FEFO, picking, staging y handoff |
| S2 | Driver; Delivery Operator; Route/Delivery Coordinator | Cubrir intento, navegación, incidencias, POD y entrega al Buyer |
| S3 | Customer Buyer; encargado de compras; responsable de recepción | Cubrir verificación, cantidades, discrepancia y confianza |

Se procurará variedad de experiencia, dispositivo, conectividad y contexto de
trabajo. No se inventarán nombres, organizaciones, métricas ni conclusiones
para llenar la muestra.

## Protocolo de observación y entrevista

1. Explicar propósito, duración, uso académico y límites de privacidad.
2. Obtener consentimiento para audio/video, captura y uso de artefactos.
3. Pedir un caso reciente; observar o reconstruir el flujo con datos
   anonimizados.
4. Registrar el caso normal y al menos una excepción relevante.
5. Identificar personas, sistemas, dispositivos, handoffs y evidencias sin
   tratar una solución propuesta como si ya existiera.
6. Confirmar con la persona qué interpretación representa su experiencia.
7. Cerrar con riesgos de adopción y una oportunidad de mejora priorizada.
8. Guardar ficha, captura, enlace individual, intervalo del consolidado,
   consentimiento y notas codificadas.

## Registro de seguridad y ética

- No capturar nombres de clientes, direcciones completas, credenciales,
  documentos fiscales, matrículas ni datos de pago innecesarios.
- Difuminar o retirar información de terceros antes de publicar una captura.
- Solicitar permiso separado para mostrar pantalla, ubicación o documentos.
- No pedir seguimiento continuo de ubicación del conductor.
- No convertir una demostración preparada por el equipo en observación real.
- Mantener la opción de retirar una captura o dato no necesario para la
  evaluación.

## Campos obligatorios del registro

| Campo | Regla |
| :--- | :--- |
| Identificador | Código estable, no el nombre de la persona |
| Segmento/rol | Etiqueta vigente y rol observado |
| Nombre, edad, distrito | Sólo datos autorizados |
| Dispositivo/conectividad | Declarado u observado, con distinción explícita |
| Fecha/duración/timing | Verificado contra grabación |
| Preguntas/respuestas | Preguntas realmente aplicadas; no reconstruidas desde el backlog |
| Evidencia | Captura, video individual, consolidado y enlaces |
| Hallazgo | Observación o cita autorizada, con interpretación separada |
| Historia afectada | `MOB-US-*` confirmada, modificada, rechazada o aún abierta |
| Revisión | Nombre del revisor y fecha de aceptación |

## Plan de análisis

La codificación inicial usará: frecuencia, costo del error, excepción,
handoff, evidencia, conectividad, privacidad, ergonomía, seguridad y adopción.
Se conservarán casos negativos y desacuerdos. Las frecuencias y porcentajes se
calcularán por segmento con el denominador de registros válidos; no se usarán
porcentajes de mercado ni estadísticas del material histórico para simular una
muestra nueva.

## Salida esperada

La campaña debe producir, por segmento, registros individuales, resumen
descriptivo, tabla de variables, actualización de personas, As-Is Journey,
Empathy Map, User Task Matrix y decisiones sobre historias. Cada artefacto debe
enlazar a su fuente y conservar el estado `OBSERVED`, `INTERPRETED`, `PROPOSED`
o `VALIDATED`.

**Estado del plan:** READY FOR HUMAN RECRUITMENT REVIEW. No existe evidencia
primaria nueva en este corte.
