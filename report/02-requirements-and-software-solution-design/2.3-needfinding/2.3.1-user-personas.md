## 2.3 Needfinding

### 2.3.1 User Personas

Las User Personas sintetizan los tres segmentos priorizados para orientar la
investigación y el diseño de Nexa Mobile. No son perfiles de autorización,
entidades de dominio ni evidencia de adopción. Los nombres son sintéticos y las
frases incluidas describen necesidades de investigación; no se presentan como
citas de participantes.

La evidencia disponible incluye dos entrevistas exploratorias a representantes
del segmento B2B Buyers. Para Warehouse & Dispatch Operations y Driver Delivery
Execution, las fichas orientan la observación de casos recientes y las
entrevistas directas que deberán completar el entendimiento del trabajo físico.
Por ello, las características no sustentadas se formulan como preguntas de
investigación, sin atribuir demografía, hábitos o resultados a personas reales.

#### Mariela Torres — Warehouse & Dispatch Operations

| Aspecto | Síntesis de investigación |
| --- | --- |
| Segmento y rol | Arquetipo para explorar las tareas de Warehouse Operator y Dispatch Coordinator sin fusionar sus responsabilidades. |
| Contexto | Recepción, identificación, preparación, readiness y Dispatch Handoff cerca de la mercadería. |
| Objetivo | Reconocer la tarea y el responsable siguiente con el contexto necesario para continuar. |
| Necesidades a contrastar | Producto, SKU, lote, cantidad, condición, prioridad, estado de preparación y evidencia de handoff. |
| Fricciones a explorar | Diferencias entre lo físico y el registro, fuentes de información dispersas, cambios de última hora y traspasos ambiguos. |
| Condiciones de uso | Trabajo físico, interrupciones, atención dividida, dispositivo compartido o conectividad variable. |
| Preguntas guía | ¿Qué información se consulta antes de continuar?, ¿qué evidencia se conserva?, ¿cuándo se detiene la tarea y a quién se escala una diferencia? |
| Criterio de aprendizaje | Identificar si un recorrido Mobile puede reducir reconstrucción y aclaraciones sin alterar la separación entre Warehouse y Dispatch. |

#### Diego Ramírez — Driver Delivery Execution

| Aspecto | Síntesis de investigación |
| --- | --- |
| Segmento y rol | Arquetipo para explorar el trabajo de Driver o Delivery Operator durante una entrega asignada. |
| Contexto | Vehículo, ruta y punto de entrega; el contexto puede cambiar entre asignación, intento, incidencia y comunicación posterior. |
| Objetivo | Ejecutar el Delivery Attempt correcto y dejar un resultado o una incidencia comprensibles para el siguiente responsable. |
| Necesidades a contrastar | Identidad de la entrega, destino, contacto autorizado, instrucciones pertinentes, evidencia permitida y estado de cada acción. |
| Fricciones a explorar | Asignaciones incompletas, contacto insuficiente, interrupciones, conectividad limitada y evidencia asociada al intento equivocado. |
| Condiciones de uso | Movimiento, presión de tiempo, batería, atención limitada, alternativa manual a cámara o escáner y privacidad de datos. |
| Preguntas guía | ¿Cómo inicia un intento reciente?, ¿qué evidencia necesita?, ¿qué ocurre ante una interrupción?, ¿cuándo requiere coordinación humana? |
| Criterio de aprendizaje | Comprobar si el recorrido mantiene separados la entrega, el intento, el resultado, la incidencia y la evidencia. |

#### Carlos Mendoza — B2B Buyers

| Aspecto | Síntesis de investigación |
| --- | --- |
| Segmento y rol | Arquetipo construido para representar al Customer Buyer que participa en abastecimiento, seguimiento y recepción desde la empresa compradora. |
| Base disponible | Dos entrevistas exploratorias muestran la importancia de anticipar llegadas, mantener canales directos de comunicación y contar con apoyo humano ante excepciones. La muestra no permite generalizar al segmento completo. |
| Contexto | Negocio comprador y punto de recepción, en coordinación con proveedor, personal interno y clientes propios. |
| Objetivo | Anticipar la llegada, reconocer lo esperado y comunicar una diferencia con suficiente contexto. |
| Necesidades a contrastar | Estado de la entrega, productos y cantidades esperados, recepción, discrepancia, evidencia pertinente y canal de soporte. |
| Fricciones a explorar | Incertidumbre de llegada, dependencia de llamadas o mensajería y dificultad de explicar un cambio o una diferencia. |
| Preguntas guía | ¿Cómo compara lo esperado con lo recibido?, ¿qué información necesita para comunicar un faltante o daño?, ¿cuándo prefiere autoservicio y cuándo contacto humano? |
| Criterio de aprendizaje | Verificar si la claridad de contexto reduce incertidumbre sin confundir Buyer Receipt con Driver Outcome. |

#### Uso de las personas

Las personas alimentan la User Task Matrix, los mapas As-Is, los Empathy Maps,
el Impact Mapping y las User Stories. Una actualización posterior debe
diferenciar con claridad lo observado, lo interpretado y lo propuesto, conservar
la fuente de cada hallazgo y evitar convertir una muestra limitada en una regla
de producto.
