# Landing Functional Stories

## Alcance

Estas seis historias describen la Landing académica de Nexa. Permanecen fuera
del catálogo `MOB-US-001..073` y no crean una tercera aplicación móvil. Se
basan en la superficie pública consultada del [Website de Nexa](https://github.com/nexa-suite/website):
propuesta B2B de cadena de frío, soluciones, precios, preguntas frecuentes,
información legal, registro, contacto y demostración.

La Landing comunica capacidades públicas; no convierte un mensaje comercial en
una promesa de comportamiento del producto ni en una confirmación de registro.

## Historias

### LAND-US-001 — Comprender la propuesta B2B de cadena de frío

| Campo | Valor |
| :--- | :--- |
| Story ID | LAND-US-001 |
| User | Visitante empresarial |
| Priority | Alta |
| Epic | LAND-EPIC-01 — Adquisición pública y onboarding |
| Product surface | Website / Landing pública |
| Story points | 2 |
| Sprint | S1 |
| Description | Como visitante empresarial, deseo comprender la propuesta B2B de Nexa para operaciones de cadena de frío, para decidir si corresponde continuar la evaluación. |

- **Scenario: Propuesta disponible** — **Given** una persona abre la Landing pública, **When** revisa la introducción del producto, **Then** identifica el contexto B2B de cadena de frío sin confundirlo con un comercio electrónico genérico.
- **Scenario: Contexto operativo claro** — **Given** la persona necesita entender el negocio objetivo, **When** revisa el contenido público, **Then** distingue los perfiles de importador, distribuidor y almacenamiento en frío que el sitio comunica.

| Story points | 3 |
| Sprint | S1 |
| Description | Como prospecto empresarial, deseo contrastar mi perfil operativo con las soluciones de Nexa, para decidir si debo iniciar una conversación o evaluación. |

- **Scenario: Perfil presentado** — **Given** el prospecto opera como importador, distribuidor o empresa de almacenamiento en frío, **When** revisa la solución correspondiente, **Then** encuentra el contexto operativo descrito por Nexa.
- **Scenario: Siguiente paso común** — **Given** el prospecto combina más de un perfil, **When** compara las soluciones, **Then** puede continuar hacia un producto, contacto o demostración sin perder el contexto consultado.

| Sprint | S1 |
| Description | Como prospecto empresarial, deseo revisar las capacidades y límites públicos del producto, para entender qué problema operativo aborda Nexa antes de continuar. |

- **Scenario: Alcance público** — **Given** el prospecto abre el contenido del producto, **When** revisa las capacidades descritas, **Then** relaciona Nexa con resultados operativos de inventario, coordinación de pedidos, cadena de frío o entrega que el sitio comunique.
- **Scenario: Límite explícito** — **Given** una capacidad no está descrita en la fuente pública, **When** el prospecto evalúa Nexa, **Then** el contenido no promete una integración o resultado no establecido.

| Description | Como prospecto empresarial, deseo iniciar el registro de un Workspace desde la Landing, para continuar por el proceso autorizado de Nexa. |

- **Scenario: Registro disponible** — **Given** el prospecto elige la acción pública de registro, **When** la Landing procesa la acción, **Then** lo dirige a la ruta autorizada sin afirmar que Tenant o Workspace ya fueron creados.
- **Scenario: Ruta no disponible** — **Given** el destino de registro no responde, **When** el prospecto elige registrarse, **Then** la Landing comunica el problema o ofrece contacto alternativo sin afirmar un onboarding exitoso.

### LAND-US-006 — Contactar a Nexa o solicitar una demostración

| Campo | Valor |
| :--- | :--- |
| Story ID | LAND-US-006 |
| User | Prospecto empresarial |
| Priority | Alta |
| Epic | LAND-EPIC-01 — Adquisición pública y onboarding |
| Product surface | Website / contacto y demostración |
| Story points | 3 |
| Sprint | S1 |
| Description | Como prospecto empresarial, deseo contactar a Nexa o solicitar una demostración, para obtener un siguiente paso comercial explícito cuando la información pública no sea suficiente. |

- **Scenario: Solicitud válida** — **Given** el prospecto proporciona el contexto requerido, **When** envía la solicitud de contacto o demostración, **Then** la Landing comunica sólo el resultado real del envío.
- **Scenario: Datos inválidos** — **Given** falta un dato obligatorio o no cumple el formato, **When** el prospecto envía la solicitud, **Then** la Landing identifica la validación pendiente y no afirma que la solicitud fue recibida.
- **Scenario: Servicio no disponible** — **Given** el servicio de contacto no responde, **When** el prospecto envía la solicitud, **Then** la Landing muestra un fallo explícito y no confirma un contacto inexistente.
