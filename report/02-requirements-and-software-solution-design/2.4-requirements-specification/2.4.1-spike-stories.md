# 2.4.1 Spike Stories

Los Spike Stories delimitan incertidumbres técnicas o de producto que requieren
investigación antes de convertir una hipótesis en una decisión. Cada registro
define una pregunta, un artefacto esperado y un criterio de cierre. Este
documento no inventa resultados.

| ID | Nombre | Objetivo | Puntos | Sprint |
| :--- | :--- | :--- | ---: | :--- |
| SPIKE-001 | Oportunidad de aprendizaje autónomo | Determinar qué oportunidad aporta valor al trabajo móvil y qué límites necesita. | 3 | S3 |
| SPIKE-002 | Bases compartidas y paridad funcional | Determinar cómo sostener dos aplicaciones y paridad funcional mediante las tres tecnologías aceptadas. | 5 | S1 |
| SPIKE-003 | Identificadores de producto | Determinar el alcance de Barcode, QR, GS1 y la alternativa manual. | 3 | S2 |
| SPIKE-004 | Persistencia y recuperación local | Determinar qué datos pueden persistir localmente y cómo recuperarlos de forma segura. | 5 | S2 |
| SPIKE-005 | Notificaciones y deep links | Determinar usos autorizados, permisos y límites de navegación iniciada por notificaciones. | 3 | S3 |
| SPIKE-006 | Mapas y ubicación | Determinar uso de mapas y ubicación respetando privacidad, batería y conectividad. | 3 | S4 |

## SPIKE-001 — Oportunidad de aprendizaje autónomo

| Campo | Valor |
| :--- | :--- |
| ID | SPIKE-001 |
| User | Developer y Product |
| Priority | Media |
| Epic | SPIKE-EPIC-01 — Investigación de producto móvil |
| Objective | Determinar qué oportunidad de aprendizaje autónomo aporta valor al trabajo móvil sin crear una autoridad paralela. |
| Question | ¿Qué resultado observable, datos, límites de privacidad y mecanismo de revisión requiere la oportunidad seleccionada? |
| Expected artifact | Matriz de oportunidades, fuentes, datos, privacidad, factibilidad y prueba acotada. |
| Completion criteria | Recomendación documentada, límites de uso definidos y ausencia explícita de afirmaciones de producción. |
| Story points | 3 |
| Planned Sprint | S3 |

## SPIKE-002 — Bases compartidas y paridad funcional

| Campo | Valor |
| :--- | :--- |
| ID | SPIKE-002 |
| User | Developer y Product |
| Priority | Alta |
| Epic | SPIKE-EPIC-02 — Estrategia de implementación móvil |
| Objective | Determinar bases compartidas y estrategia de paridad funcional para Nexa Operations Mobile y Nexa Buyer Mobile. |
| Question | ¿Cómo pueden Android Native/Kotlin, Flutter/Dart e iOS Native/SwiftUI sostener los contratos compartidos, el estado local seguro, la distribución y la paridad funcional entre las dos aplicaciones? |
| Expected artifact | Matriz comparativa de flujos, seguridad, estado local, contratos, distribución, pruebas y mantenimiento para las tres tecnologías aceptadas; prueba acotada de un flujo común. |
| Completion criteria | Trade-offs, límites, responsabilidades compartidas y diferencias permitidas de plataforma documentados. La pregunta no consiste en elegir una única tecnología ni en duplicar reglas de negocio. |
| Story points | 5 |
| Planned Sprint | S1 |

## SPIKE-003 — Identificadores de producto

| Campo | Valor |
| :--- | :--- |
| ID | SPIKE-003 |
| User | Developer y Operador de Almacén |
| Priority | Media |
| Epic | SPIKE-EPIC-03 — Capacidades del dispositivo |
| Objective | Determinar el alcance de Barcode, QR, GS1 y la alternativa manual para identificar productos, paquetes y ubicaciones. |
| Question | ¿Qué formatos, permisos, ambigüedades, expiración, reutilización y validaciones del servidor son necesarios para una identificación confiable? |
| Expected artifact | Comparación de formatos, reglas de identificación, límites de seguridad y prueba controlada en dispositivo. |
| Completion criteria | Alcance de identificadores, alternativa manual y preguntas de integración documentados sin crear un Bounded Context de dispositivo. |
| Story points | 3 |
| Planned Sprint | S2 |

## SPIKE-004 — Persistencia y recuperación local

| Campo | Valor |
| :--- | :--- |
| ID | SPIKE-004 |
| User | Developer |
| Priority | Alta |
| Epic | SPIKE-EPIC-04 — Continuidad controlada |
| Objective | Determinar qué información puede conservarse localmente y cómo recuperar cambios sin presentar éxito de negocio no confirmado. |
| Question | ¿Cómo se clasifican, protegen, reintentan y reconcilian caché, borradores, evidencia temporal y metadatos de reintento? |
| Expected artifact | Clasificación de datos, modelo de protección, secuencia de sincronización, política de conflictos y prueba de recuperación. |
| Completion criteria | Límite offline seguro documentado; inventario, compromiso, crédito, pago, entrega y recepción siguen dependiendo de confirmación autoritativa. |
| Story points | 5 |
| Planned Sprint | S2 |

## SPIKE-005 — Notificaciones y deep links

| Campo | Valor |
| :--- | :--- |
| ID | SPIKE-005 |
| User | Developer y Usuario móvil |
| Priority | Media |
| Epic | SPIKE-EPIC-05 — Comunicación contextual |
| Objective | Determinar usos autorizados de notificaciones push y deep links para llevar a una persona a un contexto móvil válido. |
| Question | ¿Qué eventos pueden iniciar una notificación, cómo se comprueban Tenant y permisos, y cómo expiran o se repiten los enlaces? |
| Expected artifact | Matriz de evento, canal, permiso, ámbito, expiración, reintento y destino permitido. |
| Completion criteria | Reglas de navegación y seguridad documentadas; una notificación no cambia por sí sola el estado de negocio. |
| Story points | 3 |
| Planned Sprint | S3 |

## SPIKE-006 — Mapas y ubicación

| Campo | Valor |
| :--- | :--- |
| ID | SPIKE-006 |
| User | Developer y Conductor u Operador de Entrega |
| Priority | Media |
| Epic | SPIKE-EPIC-06 — Navegación responsable |
| Objective | Determinar el uso móvil de mapas y ubicación respetando privacidad, batería y conectividad. |
| Question | ¿Qué destino, permiso, observación del dispositivo, alternativa y límite de retención son necesarios para apoyar una entrega? |
| Expected artifact | Comparación de navegación externa, permisos, consumo, conectividad y alternativas de operación. |
| Completion criteria | Límite mínimo documentado; el alcance inicial se mantiene en navegación externa autorizada y no en seguimiento continuo. |
| Story points | 3 |
| Planned Sprint | S4 |
