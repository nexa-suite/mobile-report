# 2.4.1 User Stories

Las historias se organizan por tipo y release para que cada tarjeta mantenga los
campos exigidos por el curso: Story ID, User, Priority, Epic, Title,
Description y Acceptance Criteria. Functional Stories expresan outcomes de
negocio; Landing Stories cubren adquisición e inicio de onboarding; Technical
Stories habilitan capacidades sin ser autoridad de negocio; y Spike Stories
reducen incertidumbre antes de una decisión.

La prioridad visible y el orden del Product Backlog son una proyección
académica por valor de negocio. El release y la metadata de ciclo de vida del
Blueprint conservan su propia autoridad; una dependencia técnica no determina
el valor de una historia para el Product Backlog.
