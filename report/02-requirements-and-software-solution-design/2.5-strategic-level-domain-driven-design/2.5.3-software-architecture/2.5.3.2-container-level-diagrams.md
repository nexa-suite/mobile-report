# 2.5.3.2 Software Architecture Container-Level Diagrams

El Container Diagram deberá representar los elementos ejecutables o almacenes que componen Nexa:

| Container | Responsabilidad |
|---|---|
| Nexa Website | Descubrimiento público, contacto e ingreso. |
| Nexa Platform | Operación de la workforce interna. |
| Nexa Buyer Portal | Autoservicio del comprador B2B. |
| Nexa API | Autoridad de dominio, seguridad, workflows, integraciones y persistencia. |
| PostgreSQL | Persistencia transaccional y configuración lógicamente aislada. |
| Object Storage | Bytes de documentos y media asociados a la operación. |

Operations Mobile y Buyer Mobile son containers `V1 TARGET / PLANNED / PROPOSED`.
Son clientes planificados para V1, no capacidades implementadas, y no se
separan en backends propios. El API modular monolith mantiene la autoridad
transaccional y las superficies consumen sus contratos.

## Technology and communication baseline

| Container | Technology evidence or target | Communication and boundary |
| :--- | :--- | :--- |
| Nexa Website | HTML5/CSS3/vanilla JavaScript source is available in the Website repository | Public discovery and contact; no Mobile authority |
| Nexa Platform | Existing product surface; implementation version must be cited from its repository | Internal workforce workflows through API contracts |
| Nexa Buyer Portal | Existing product surface; implementation version must be cited from its repository | Authorized buyer relationship through API contracts |
| Nexa API | Java 25, Spring Boot 4.1 and Spring Modulith candidate baseline | REST contracts, authorization, transactions and integrations |
| PostgreSQL | Shared relational persistence | Logical ownership by Bounded Context; tenant-scoped access |
| Object Storage | Target storage for document/evidence bytes | Authorized references; no public URL assumed |
| Operations Mobile | Target client; framework remains open under SPIKE-002 | Consumes API; local state is non-authoritative |
| Buyer Mobile | Target client; framework remains open under SPIKE-002 | Consumes API; receipt/discrepancy commands remain server-authorized |

External Payment Provider, Email Delivery Service and Maps & Geolocation
Provider remain abstract systems until a provider is selected and demonstrated.
