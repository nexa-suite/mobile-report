# Software Architecture Components Overview

Esta vista es un encabezado descriptivo dentro de 2.5.3. El rubric visible
reserva la numeración 2.5.3.1 para Context, 2.5.3.2 para Container y 2.5.3.3
para Deployment. La vista de componentes no se numera artificialmente aquí.

Los componentes se muestran como lentes selectivos dentro de Nexa API o de las
superficies clientes. No son Bounded Contexts, no redefinen el mapa estratégico
y no sustituyen los diagramas tácticos de la sección posterior.

## Familias de componentes del API

| Familia C4 | Capacidades observadas en el diseño | Límite estratégico |
| :--- | :--- | :--- |
| Identity, Tenant & Customer | Identity, tenant/workspace, customer y buyer relationship adapters | Sirve BC-01 y BC-02 sin fusionar sus autoridades |
| Commercial & Inventory | Catálogo/política, compromiso comercial, disponibilidad y protección | Proyecta BC-03/04/05; no convierte cada módulo en container |
| Fulfillment & Delivery | Fulfillment, dispatch, handoff, delivery y continuidad | Sirve BC-06 y conserva delivery outcome/POD separados |
| Credit, Payment & Documents | Crédito/receivables, pagos, documentos y provider ACL | Sirve BC-07/08/09 sin hacer Finance genérico |
| Integration Reliability | Outbox, inbox/deduplication, retries y publicación de hechos | Soporta BC-10/11 sin ser un nuevo BC |

Las familias anteriores representan cortes de lectura del API. El ownership
lógico sigue siendo el de los once contextos accepted; PostgreSQL compartido no
crea un componente propietario común.

## Proyecciones de cliente

Operations Mobile y Buyer Mobile se representan como componentes de sus
containers planificados:

| Proyección | Componentes de lectura | Regla de autoridad |
| :--- | :--- | :--- |
| Operations Mobile | Session/context client, work projection, command/retry coordinator, evidence staging | Mutaciones autorizadas por Nexa API; recursos del dispositivo requieren permiso y fallback |
| Buyer Mobile | Session/context client, delivery projection, handoff/receipt flow, discrepancy evidence | Receipt, discrepancy y confirmaciones siguen siendo hechos autorizados por servidor |
