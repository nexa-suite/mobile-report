# 2.5.3.3 Software Architecture Component-Level Diagrams

Esta sección se incorpora para cubrir el componente de arquitectura solicitado por el enunciado. Los diagramas deberán mostrar componentes dentro de los containers, sin confundirlos con Bounded Contexts.

La fuente de referencia observada es la cobertura de componentes de C4 en
`blueprint/01-shared/architecture/c4/structurizr/l3`. Las vistas móviles se
tratarán como propuestas y las vistas del API se presentarán según la evidencia
de implementación o de diseño disponible.

## Candidate component boundaries

| Container | Components to verify | Boundary rule |
| :--- | :--- | :--- |
| Nexa API | Interface/REST adapters, application handlers, domain modules, persistence ports, integration adapters | A component may serve a Bounded Context capability; it is not automatically a context or deployment |
| Operations Mobile | Session/context client, work projection, command/retry coordinator, evidence staging and navigation adapter | All business mutations remain API-authorized; device resources require explicit permission and fallback |
| Buyer Mobile | Session/context client, delivery projection, handoff/receipt flow, discrepancy evidence and notification/deep-link handler | Verification, receipt and discrepancy remain separate states and facts |

These are candidate design boundaries, not a claim that the components exist in
the current Mobile repository. A final diagram must name the selected
container, source file or approved design decision, interfaces, dependencies,
and render revision.

## Estado de evidencia

Existen fuentes DSL y exports versionados, incluidos
`Nexa-Operations-Mobile-TARGET` y `Nexa-Buyer-Mobile-TARGET`. Falta seleccionar
los containers que se detallarán, incorporar los exports y registrar la
explicación/revisión humana de responsabilidades e interacciones.
