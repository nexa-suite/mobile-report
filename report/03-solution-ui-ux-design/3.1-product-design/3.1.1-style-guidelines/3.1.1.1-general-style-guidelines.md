# 3.1.1.1 General Style Guidelines

## Origen y estado

El origen visual actual es Nexa Design Lab v1.0.2, en la revisión principal
registrada en la [línea base vigente](../../../../delivery-checklists/live-baseline.md).
Es evidencia ejecutable de diseño, no un release de producto Mobile. La
implementación Mobile propuesta debe consumir aliases de las capas de tokens,
en lugar de copiar valores directos en cada pantalla.

## Token architecture

| Layer | Purpose | Example documented role | Mobile rule |
| :--- | :--- | :--- | :--- |
| Primitive | Raw palette, spacing, radius, typography and shadow values | `nexa-primitive-blue-600`, `nexa-space-4` | Change rarely; never use as a screen-specific shortcut |
| Semantic | Meaning and state | `nexa-color-primary-600`, text, surface, status and focus roles | Use for intent, contrast and theme/evaluation modes |
| Component | Control and layout geometry | `nexa-control-height-md`, `nexa-target-size-min` | Use for buttons, fields, status, navigation and touch targets |

Los archivos de origen son primitive.tokens.json, semantic.tokens.json y
component.tokens.json en el repositorio Design Lab. El SCSS generado no se
edita manualmente. Toda extracción futura de tokens para Mobile debe conservar
la cadena de aliases y registrar la revisión de origen.

## Visual direction

- Light appearance is canonical; dark mode is deferred.
- White structural surfaces sit on a cool light canvas with restrained,
  purposeful elevation.
- Rounded geometry is semantic: controls, cards, panels and compact status do
  not share one universal radius.
- Plus Jakarta Sans, Inter and JetBrains/system mono are candidate families;
  the final Mobile selection remains a team decision.
- PrimeIcons are a candidate icon system; icons require a visible label or
  equivalent accessible name and must not carry business meaning alone.
- Increased Contrast, Reduced Motion and 400% reflow are evaluation modes to
  carry into the Mobile accessibility review, not certifications.

## Component state minimum

| Component family | Required states | Mobile-specific review |
| :--- | :--- | :--- |
| Button / command | Rest, focus, pressed, disabled, pending, success, error | Idempotent retry and clear unknown result |
| Text field / quantity | Empty, valid, invalid, read-only, focused, unavailable | Numeric input, unit and validation announced |
| Status / timeline | Current, pending, failed, expired, confirmed | Distinguish receipt, POD, outcome, discrepancy and notification |
| Navigation / handoff | Active, deep-linked, unauthorized, offline/unavailable | Re-check authorization before protected destination |
| Evidence capture | Permission, captured, rejected, upload pending, upload failed | Never imply proof or completion before server confirmation |

## Responsive and accessibility rules

El objetivo usa layouts content-first, un target interactivo mínimo de 44px
cuando sea posible, equivalentes visibles de teclado/focus, texto de estado
legible, contraste suficiente, alternativas de movimiento reducido y reflow sin
pérdida de información. La validación en 1440, 1024, 768, 390 y 320px es un
gate de Design Lab; Mobile también requiere revisión en un dispositivo real.
Ningún gate se ha ejecutado para la superficie Mobile en este corte.
