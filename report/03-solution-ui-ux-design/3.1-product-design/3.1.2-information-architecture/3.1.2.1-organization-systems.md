### 3.1.2. Arquitectura de la información

#### 3.1.2.1. Sistemas de organización

La arquitectura de información de Nexa organiza el contenido según la responsabilidad de la superficie, el rol de la persona y el objetivo que debe completar. La estructura pública del Website favorece el descubrimiento y la comprensión del producto; las superficies operativas priorizan la continuidad del trabajo, el contexto autorizado y la confirmación de resultados.

##### Principios de organización

- **Responsabilidad antes que estructura interna.** La persona debe encontrar una tarea o una respuesta, no navegar por los Bounded Contexts del sistema.
- **Contexto antes que comando.** Antes de mostrar una acción sensible se debe hacer visible el workspace, la entrega, el comprador o el ítem al que se aplica.
- **Trabajo actual antes que historial.** La información necesaria para completar la tarea debe aparecer antes que los registros anteriores, sin ocultar el historial cuando sea necesario para verificar.
- **Resultado junto a la acción.** La confirmación, el estado pendiente o la excepción deben permanecer relacionados con el comando que los produjo.
- **Recuperación sin pérdida de contexto.** Volver, reintentar o corregir no debe borrar silenciosamente el estado anterior ni convertir un resultado incierto en éxito.

##### Website público

El Website organiza el contenido en grupos de producto, solución, empresa, precios, preguntas frecuentes, buyer portal, plataforma y áreas legales. Esta jerarquía favorece el descubrimiento público y la decisión informada; no representa una navegación operativa autorizada.

Las páginas de solución se agrupan por el problema o el contexto del negocio, mientras que las páginas de producto y plataforma explican capacidades. El contenido legal permanece accesible desde el pie de página y no debe mezclarse con acciones comerciales o de operación.

##### Estructura propuesta para las superficies Mobile

*Estructura de información propuesta para las superficies Mobile.*

| Superficie | Contexto inicial | Jerarquía principal | Resultado esperado |
| :--- | :--- | :--- | :--- |
| Operations Mobile | Workspace y trabajo autorizado | Trabajo asignado → detalle → comando o evidencia → resultado → historial | Alejandro registra preparación y transferencia; Diego registra el intento de entrega y su evidencia. |
| Buyer Mobile | Relación autorizada y entrega | Atención de entrega → verificación de transferencia → cantidades → receipt o discrepancy → historial | Carlos confirma lo recibido o deja registrada una diferencia sin borrar el hecho original. |
| Sitio web | Necesidad del visitante | Problema → solución → capacidad → evidencia o límite → CTA | La persona entiende el valor de Nexa y sabe cuál es la siguiente acción. |

La organización es secuencial para un comando, pero las vistas de lista y detalle pueden ser matriciales cuando el rol tiene varios elementos asignados. La persona debe poder volver al trabajo actual sin perder el estado visible; los datos protegidos solo se muestran después de confirmar sesión, Tenant/Workspace y autorización.

| Rol | Secuencia prioritaria | Unidad de información que debe permanecer visible |
| :--- | :--- | :--- |
| Alejandro | Contexto → asignación → Product/SKU → preparación → transferencia de despacho | Identidad del ítem, lote o vencimiento, cantidad autorizada y resultado de la transferencia. |
| Diego | Asignación → Delivery Attempt → resultado → evidencia | Entrega, intento actual, cantidades, motivo de excepción y estado de evidencia. |
| Carlos | Entrega → código de transferencia → cantidades → Buyer Receipt o Discrepancy | Relación autorizada, cantidades esperadas y recibidas, diferencia y estado de confirmación. |

*Nota.* La estructura ordena objetivos y capacidades de usuario; no representa una navegación por Bounded Contexts ni un contrato de API.

El inventario de páginas, sus etiquetas y la agrupación de pantallas constituyen la base para wireframes y wireflows. Esta entrega completa la organización textual; la representación visual de esas pantallas se mantiene como trabajo posterior.
