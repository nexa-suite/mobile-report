#### 3.1.2.3. Etiquetas SEO y metadatos

Los metadatos del Website deben describir cada página de forma consistente y separar el contenido que ayuda al descubrimiento de cualquier afirmación sobre despliegue, indexación o conversión. La información visible para buscadores y redes sociales debe conservar el mismo posicionamiento que la página.

##### Criterios de metadatos para el Website

El Website debe incorporar, en la página principal y en cada página pública de
producto, soluciones, empresa, preguntas frecuentes y áreas legales:

- atributo de idioma HTML;
- viewport responsive;
- title específico por página;
- meta description específica por página;
- robots con intención de indexación;
- theme color alineado con la identidad;
- Open Graph title, description, type, URL y site name;
- URL canónica;
- tarjeta de Twitter cuando corresponde.

La página principal usa contenido localizado mediante claves de traducción para title, description y Open Graph. Las páginas internas mantienen títulos y descripciones asociados a su contexto, por ejemplo producto, plataforma, buyer portal, pricing, FAQ, soluciones y documentos legales.

| Metadato | Función | Criterio de Nexa | Estado en este informe |
| :--- | :--- | :--- | :--- |
| lang | Identificar el idioma del documento | Debe corresponder al contenido predominante de la página | Regla definida; auditoría por página pendiente. |
| title | Identificar la página en pestañas y resultados | Único, descriptivo y alineado con el encabezado principal | Regla definida; valores concretos pendientes de auditoría. |
| description | Resumir la propuesta de la página | Describir el contenido real sin prometer capacidades no disponibles | Regla definida; valores concretos pendientes de auditoría. |
| canonical | Evitar ambigüedad de URL principal | Apuntar a la URL canónica de la página | Requerido; debe comprobarse en el entorno de publicación. |
| Open Graph | Controlar la vista previa social | Mantener title, description, type, URL y site name coherentes | Requerido; revisión visual de vistas previas pendiente. |
| robots | Expresar intención de rastreo | No reemplaza una política de publicación ni una comprobación de indexación | Requerido según política de publicación; auditoría pendiente. |
| idioma localizado | Mantener consistencia entre contenido y metadatos | Cambiar title, description y Open Graph junto con el contenido | Criterio definido; catálogo de traducciones pendiente. |

##### Mobile y ASO

Operations Mobile y Buyer Mobile requieren nombre, descripción breve y larga, icono, capturas, destino de privacidad y notas de release solo cuando se seleccione un cliente distribuible. Esta definición depende de una decisión de release y no debe confundirse con la documentación de UX/UI.

Las etiquetas operativas Mobile no deben optimizarse a costa de autorización, seguridad o trazabilidad. Un texto orientado a descubrimiento nunca debe declarar como confirmado un resultado que todavía está pendiente.

##### Límite de evidencia

La definición de estos metadatos no demuestra despliegue, rastreo, indexación,
rendimiento de búsqueda, conversión ni correcta visualización de vistas
previas sociales. En este informe no se presenta una auditoría de código o de
entorno de publicación como evidencia cerrada. Para completar la subsección
faltaría revisar cada página, comprobar las URLs canónicas en el entorno de
publicación y contrastar las vistas previas en los canales previstos.
