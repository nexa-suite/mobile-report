#### 3.1.2.4. Sistemas de búsqueda

##### Alcance actual

Las historias priorizadas no autorizan una capacidad de búsqueda global genérica para todas las superficies. El Website proporciona navegación pública y contenido de páginas; el informe no afirma una búsqueda operativa autenticada ya implementada.

La búsqueda Mobile debe existir solo donde reduzca tiempo o error en una tarea concreta. El resultado debe respetar el workspace y el rol autorizados; buscar no concede acceso, modifica datos ni confirma un hecho de negocio.

##### Necesidades de búsqueda para Mobile

*Necesidades de búsqueda y acceso previstas para Mobile.*

| Necesidad | Superficie | Requisitos del resultado | Estado |
| :--- | :--- | :--- | :--- |
| Identificar Product/SKU, lote o vencimiento | Operations Mobile | Workspace autorizado, identificador, contexto de lote o vencimiento y alternativa manual | Requiere evaluación de SPIKE-003. |
| Encontrar trabajo asignado | Operations Mobile | Lista limitada por rol, estado actual e identidad estable de Delivery o Attempt | Requiere contrato de aplicación. |
| Abrir una entrega del comprador | Buyer Mobile | Buyer Relationship autorizada, código de transferencia o actualización permitida | Cubierto por MOB-US-044 y MOB-US-047. |
| Recuperar un resultado no resuelto | Operations o Buyer Mobile | Identidad del comando, última respuesta confirmada y acción segura de retry | Debe definirse junto con el contrato de idempotencia. |

##### Estados y anatomía del resultado

Todo resultado de búsqueda debe mostrar, como mínimo, su contexto de origen, identidad estable, estado actual y última hora confirmada. Cuando el dato pueda tener lote, vencimiento, cantidad o temperatura, esos atributos deben aparecer antes de una acción irreversible.

| Estado | Qué debe comunicar | Acción disponible |
| :--- | :--- | :--- |
| Inicial | Qué puede buscar la persona y en qué alcance | Escribir, escanear o seleccionar el contexto permitido. |
| Cargando | Que la consulta continúa y qué alcance está consultando | Cancelar cuando sea seguro; no duplicar la consulta. |
| Con resultados | Identidad, contexto, estado y última confirmación | Abrir el detalle o continuar con la tarea autorizada. |
| Sin resultados | Que el alcance no produjo coincidencias | Revisar término, contexto o usar alternativa manual. |
| Ambiguo | Que hay varias coincidencias posibles | Elegir por atributos distintivos; no seleccionar silenciosamente. |
| No autorizado | Que existe una restricción de acceso | Volver a un estado seguro o solicitar el contexto permitido. |
| No disponible | Que la fuente no puede confirmarse ahora | Reintentar, conservar el término o continuar sin cierre falso. |
| Expirado o desactualizado | Que el resultado no es válido para ejecutar el comando | Actualizar o volver a consultar antes de actuar. |

Los índices locales pueden ayudar a la presentación y a la continuidad offline, pero no pueden conceder acceso ni confirmar un hecho de negocio. La búsqueda debe distinguir entre el resultado almacenado localmente, la última respuesta confirmada y el estado pendiente de sincronización.
