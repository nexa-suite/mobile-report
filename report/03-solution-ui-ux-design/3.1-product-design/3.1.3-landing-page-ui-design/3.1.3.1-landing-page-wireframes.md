### 3.1.3. Landing Page UI Design

El Website público aporta una referencia de contenido para la Landing Page. La
estructura propuesta mantiene una jerarquía legible en desktop y en navegador
Mobile, sin presentar el código Website como un paquete de wireframes.

#### 3.1.3.1. Landing Page Wireframe

##### Especificación estructural

| Vista | Regiones | Regla responsive |
| :--- | :--- | :--- |
| Navegador desktop | Encabezado, hero, problema operativo, áreas de solución, límites o prueba, CTA y pie | El hero de dos columnas puede contraerse al reducirse el ancho disponible |
| Navegador Mobile | Encabezado compacto o menú, hero de una columna, prueba apilada, CTA y pie | Conservar orden de lectura, etiquetas y tamaño de objetivo interactivo |

Esta entrega describe la composición esperada, pero no incluye un wireframe
visual de Figma, Lucidchart u otra herramienta. El artefacto posterior deberá
hacer visibles jerarquía, prioridades de contenido, interacción y estados de
recuperación.

##### Criterios de composición

- La jerarquía de contenido debe mantenerse entre desktop y navegador Mobile.
- El destino del CTA y la semántica de contacto deben ser explícitos.
- Metadatos, idioma y enlaces legales deben tener representación visible.
- El reflujo a 320 px y la navegación por teclado o foco deben evaluarse antes
  de declarar accesibilidad de la página.
