#### 3.1.3.2. Mock-ups de la Landing Page

El mock-up traduce la estructura del wireframe al lenguaje visual de Nexa. Su
función es mostrar cómo conviven jerarquía, tipografía, color, espaciado,
tarjetas, botones y estados dentro de las páginas públicas. La referencia es
el Website actual y su organización de páginas; el mock-up académico conserva
la separación entre una superficie informativa y las pantallas autenticadas
del producto.

La composición debe comunicar una propuesta B2B clara, mantener visibles los
límites del alcance y conducir a una siguiente decisión comprensible. Los
mensajes sobre implementación, acceso o estado comercial deben conservar el
mismo nivel de certeza que el contenido público y no presentar una capacidad
objetivo como disponibilidad productiva.

##### Criterios visuales comunes

| Criterio | Aplicación en el mock-up |
| :--- | :--- |
| Identidad | Uso consistente del logotipo, azul de acción, superficies claras y tonos de texto definidos en las guías de estilo |
| Jerarquía | Título principal, explicación breve, acción prioritaria y contenido secundario claramente diferenciados |
| Navegación | Encabezado reconocible, rutas públicas agrupadas y retorno visible hacia el alcance del producto |
| Conversión | Acciones de alcance, información del producto y acceso etiquetadas según su destino real |
| Estados | Estado de implementación, límites y disponibilidad expresados con texto y no únicamente con color |
| Componentes | Cards, botones, badges, bloques de información y pie de página con una misma lógica visual |
| Responsive | Reflujo de columnas, reducción de densidad y conservación del orden semántico en navegador Mobile |
| Inclusión | Contraste, lectura clara, nombres comprensibles y objetivos táctiles distinguibles |

##### Composición desktop

La vista desktop presenta una navegación global amplia y un hero con suficiente
espacio para relacionar el mensaje de Nexa con el contexto operativo. La página
de inicio puede mostrar el mensaje y las acciones en una composición dividida;
las secciones posteriores agrupan la conexión de flujos, los dominios del
producto, las rutas por segmento y el estado público. El uso de tarjetas debe
servir para comparar o agrupar contenido, no para fragmentar cada frase de la
narrativa.

Las páginas de Plataforma y Buyer Portal conservan el mismo encabezado y
tratamiento de hero, pero centran el contenido en sus respectivos módulos. El
hub de Soluciones y sus tres páginas de segmento usan una plantilla editorial
común: situación del segmento, alcance que se propone ordenar, capacidades
relacionadas y acción de orientación. Empresa, FAQ, Sobre el producto, Sobre el
equipo y Estado comercial reducen la densidad visual para favorecer la lectura
informativa. Login mantiene la misma identidad y aclara que el acceso web está
en preparación.

*Tratamiento visual de las vistas públicas en desktop.*

| Vista | Composición principal | Propósito visual |
| :--- | :--- | :--- |
| Inicio | Hero, propuesta, flujo, dominios, segmentos, estado y CTA | Comunicar el valor completo y orientar la primera decisión |
| Plataforma | Hero de alcance, módulos, flujos objetivo, límites y CTA | Explicar qué organiza el producto y qué permanece abierto |
| Buyer Portal | Hero de relación de compra, catálogo, solicitud, pedido y documentos | Mostrar la continuidad conceptual del comprador autorizado |
| Soluciones | Encabezado editorial y tarjetas de segmento | Separar los tres contextos sin perder unidad de marca |
| Importadores y mayoristas | Problema del segmento, modelo de recepción y alcance | Priorizar abastecimiento, lotes y disponibilidad |
| Distribuidores | Desconexión operativa, flujo objetivo y capacidades | Priorizar solicitudes, preparación y despacho B2B |
| Operadores de cámaras frías | Necesidades del segmento y modelo de alcance | Explicar almacenamiento refrigerado sin prometer monitoreo activo |
| Empresa | Contexto del producto, estado, equipo y contribución | Reforzar confianza y transparencia |
| Estado comercial | Estado de publicación de planes y orientación | Informar sin presentar precios no publicados |
| FAQ | Preguntas agrupadas y respuestas breves | Reducir incertidumbre antes de continuar |
| Sobre el producto y Sobre el equipo | Narrativa editorial y perfiles | Explicar alcance y responsabilidades del proyecto |
| Login | Estado de acceso web y retorno al producto | Informar con claridad sin simular una sesión |
| Términos, privacidad y cookies | Texto legal, almacenamiento y preferencias | Dar soporte institucional con lectura sobria |

##### Composición Mobile

En navegador Mobile, el mock-up conserva la identidad de desktop y reorganiza
la página para una lectura vertical. La navegación se compacta en un menú; el
hero concentra el mensaje y las acciones; las tarjetas se apilan; y cada
sección mantiene su título, explicación y estado. El CTA principal debe seguir
siendo reconocible después del reflujo y los enlaces legales deben permanecer
accesibles al final de la página.

La adaptación no consiste en reducir proporcionalmente la vista desktop. El
contenido secundario se ordena después de la propuesta y se evita que una
columna demasiado estrecha o una etiqueta truncada oculte una condición del
producto. La página Login, el estado comercial y los avisos legales conservan
la misma regla: informar el estado real sin convertir una pieza visual en una
promesa de disponibilidad.

*Criterios visuales para navegador Mobile.*

| Criterio | Aplicación |
| :--- | :--- |
| Encabezado | Marca, menú compacto y estado de la página sin desplazar la propuesta |
| Hero | Una columna, título legible, explicación breve y CTA próximo |
| Tarjetas | Una por bloque de contenido, con separación suficiente y orden de lectura claro |
| Acciones | Botones con área táctil diferenciada y etiquetas que expresen su destino |
| Estado | Mensajes de alcance, implementación y acceso visibles junto a su contexto |
| Tipografía | Escala y salto de línea que mantengan títulos, datos y límites legibles |
| Pie de página | Navegación editorial, equipo, FAQ, páginas legales y cookies en orden vertical |

##### Relación con el Website y las guías de estilo

El mock-up debe conservar la composición pública observable en el Website:
una identidad azul y clara, una navegación editorial común, páginas de
soluciones agrupadas, bloques de producto con estados explícitos y un cierre
legal accesible. Las guías de estilo del apartado 3.1.1 aportan los roles de
color, tipografía, espaciado, componentes y reglas de accesibilidad; la
arquitectura de información del apartado 3.1.2 aporta el orden y las
relaciones entre páginas.

El contenido visual se limita a las páginas públicas descritas en esta
sección. No representa el catálogo autenticado, el workspace, los flujos de
Operations Mobile ni el Buyer Portal operativo. Esa distinción permite que el
mock-up comunique el producto sin atribuir al Website una autorización o una
capacidad de negocio que corresponde a otra superficie.
