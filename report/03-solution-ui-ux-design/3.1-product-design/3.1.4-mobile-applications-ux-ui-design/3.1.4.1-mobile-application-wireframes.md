# 3.1.4.1 Mobile Applications Wireframes

## Inventario de pantallas — TARGET

| Surface | Screen/state | Story traceability | Required states |
| :--- | :--- | :--- | :--- |
| Both | Session return and context selection | MOB-US-001..003 | Valid, expired, revoked, unavailable, safe retry |
| Operations | Assigned work and Product/SKU identification | MOB-US-011..019 | Empty, unauthorized, ambiguous, lot/expiry, manual fallback |
| Operations | Dispatch readiness and handoff | MOB-US-020..025 | Incomplete, exception, ready, handed off, duplicate attempt |
| Operations | Delivery execution and proof | MOB-US-026..034 | Assigned, navigation handoff, attempt, partial/rejected, proof pending/confirmed |
| Buyer | Delivery attention and handoff verification | MOB-US-044, MOB-US-047 | Relevant update, invalid/expired code, unavailable confirmation |
| Buyer | Receipt and discrepancy | MOB-US-048..049 | Matching quantities, difference, missing evidence, retry/unknown result |

Son requisitos de wireframe, no capturas. El artefacto visual debe mostrar la
jerarquía, prioridad de contenido, interacción, estado y recuperación de cada
fila, e identificar el Bounded Context propietario.
