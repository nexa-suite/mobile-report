#### 3.1.4.2. Diagramas de wireflow de aplicaciones Mobile

##### Especificación de wireflows

| Objetivo de usuario | Camino principal | Recuperación | Historias |
| :--- | :--- | :--- | :--- |
| Retomar trabajo autorizado | Regresar → confirmar sesión → seleccionar contexto → trabajo permitido | Sesión expirada, revocada o no disponible → autenticación o estado seguro | MOB-US-001..003 |
| Registrar trabajo de almacén | Abrir asignación → identificar ítem → registrar hecho autorizado → resultado confirmado | Ítem desconocido, lote o vencimiento faltante, comando duplicado o red fallida → alternativa manual, reintento o pendiente | MOB-US-011..019 |
| Transferir una entrega preparada | Revisar trabajo → confirmar preparación → Dispatch Handoff → resultado visible | Preparación incompleta o transferencia duplicada → preservar estado previo y explicar excepción | MOB-US-020..025 |
| Registrar evidencia de entrega | Abrir Delivery → navegación externa → intento o resultado → evidencia → código | Resultado parcial o rechazado, permiso denegado o carga fallida → estado no resuelto visible | MOB-US-026..034 |
| Confirmar recepción del comprador | Actualización → verificar código → confirmar cantidades → receipt o discrepancia | Código inválido, cantidades distintas o sin conexión → no confirmar falsamente la recepción | MOB-US-044, MOB-US-047..049 |

No se incluye un diagrama visual de wireflow. La tabla conserva trazabilidad
para su elaboración posterior y no demuestra una interacción Mobile ejecutada.
