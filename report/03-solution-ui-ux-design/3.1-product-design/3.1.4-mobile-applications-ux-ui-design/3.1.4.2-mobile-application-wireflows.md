# 3.1.4.2 Mobile Applications Wireflow Diagrams

## Required wireflows — TARGET

| User Goal | Happy path | Unhappy/recovery path | Stories |
| :--- | :--- | :--- | :--- |
| Resume authorized work | Return → confirm session → select context → permitted work | Expired/revoked/unavailable → authenticate or safe unavailable state | MOB-US-001..003 |
| Record warehouse work | Open assignment → identify item → record allowed fact → confirmed result | Unknown item, missing lot/expiry, duplicate command or network failure → manual fallback/retry/pending | MOB-US-011..019 |
| Hand off prepared delivery | Review work → readiness → Dispatch Handoff → visible handoff result | Incomplete preparation or duplicate handoff → preserve prior state and show exception | MOB-US-020..025 |
| Complete delivery evidence | Open Delivery → external navigation → attempt/outcome → proof → code | Partial/rejected result, permission failure or proof upload failure → unresolved visible state | MOB-US-026..034 |
| Confirm buyer receipt | Update → verify code → confirm quantities → receipt/discrepancy | Invalid code, different quantities or no connection → no false receipt and separate facts | MOB-US-044, MOB-US-047..049 |

The final wireflow must be rendered with a source file, date, viewport and
reviewer. This table is not a substitute for the diagram.
