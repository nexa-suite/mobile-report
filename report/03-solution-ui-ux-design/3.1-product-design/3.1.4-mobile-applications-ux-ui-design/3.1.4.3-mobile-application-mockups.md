#### 3.1.4.3 Mobile Applications Mock-ups

Los mock-ups deben asociar cada vista con un objetivo y un estado reconocible. La guía de estilo aplica a ambas superficies, pero sus tareas, datos y decisiones se mantienen separados.

| Superficie | Vistas que representa | Estados que deben distinguirse | Trazabilidad de la vista |
| --- | --- | --- | --- |
| Operations Mobile | Acceso/contexto, trabajo de almacén, transferencia y entrega asignada | Listo, cargando, sin permiso, error, pendiente y confirmado. | Actor, objetivo de usuario, historia, estado de interacción y recuperación. |
| Buyer Mobile | Atención de entrega, verificación, cantidades y discrepancia | Código inválido, diferencia, resultado incierto y recepción confirmada. | Customer Buyer, objetivo de usuario, historia, estado de interacción y recuperación. |
| Criterio adaptable para ambas superficies | Composición en anchos de 320 y 390 CSS px | Foco perceptible; contraste de texto y controles; espaciado de texto; preferencia de movimiento reducido. | Asociar cada ajuste visual con la vista, estado y objetivo que lo requiere. |

Las capturas de User Flow Diagrams muestran secuencias de pantallas de una aplicación; no se presentan como mock-ups estáticos ni como validación de diseño. El contenido visible debe conservar jerarquía, tamaño de texto, contraste, foco y áreas táctiles de la guía general.

La ficha de cada vista vincula el objetivo de usuario con la historia correspondiente, el actor y el estado que se representa. El estado visual identifica la interacción; el resultado del Driver y la recepción del Buyer conservan significados separados.
