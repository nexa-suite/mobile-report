##### Jerarquía visual y comunicación de estado

La guía 3.1.1 establece la identidad compartida. En estas láminas se observa énfasis azul en acciones principales, superficies claras, tarjetas, navegación inferior y mensajes acompañados de texto. Operations prioriza el objeto físico y el trabajo; Buyer, la consulta del producto y su información comercial. La similitud visual no intercambia tareas ni permisos entre aplicaciones.

*Tabla 3.1.4.3-1. Correspondencia entre tratamiento visual y alcance funcional.*

| Familia | Alta fidelidad disponible | Interpretación permitida |
| --- | --- | --- |
| OP-02 · identificación | Mosaico Operations y user flow homólogo | Consulta manual y alternativas visibles; no lectura exitosa demostrada ni mutación de stock. |
| OP-03 · recepción | User flow de recepción en 3.1.4.4 | Formulario, selección de producto y bloqueo; no recepción confirmada. |
| OP-04 · picking | User flow de preparación en 3.1.4.4 | Asignación visible y resultado incierto; no picking completado. |
| OP-09 y OP-11 | Notas de alcance | No existe pantalla reproducida de salida/traspaso ni resultado del conductor en el conjunto. |
| OP-10 y OP-12 | User flows de asignaciones y menú en 3.1.4.4 | Indisponibilidad y opciones visibles; sin inicio de intento ni código alcanzado. |
| BY-02 · catálogo | Mosaico Buyer y user flow homólogo | Catálogo y detalle visibles; no reserva ni pedido confirmado. |
| BY-03 y BY-11 | User flows de solicitud y seguimiento en 3.1.4.4 | Estados de servicio no disponible; sin borrador, envío o recepción acreditados. |

Las escenas de alta fidelidad adicionales se mantienen en sus propios user flows, sin atribuir al mosaico OP-02 cobertura de todas las tareas Operations ni al mosaico BY-02 cobertura completa de Buyer.

##### Accesibilidad y fidelidad

El diseño requiere mensajes que expliquen el resultado y la recuperación, información de estado que no dependa solo del color y una alternativa manual al uso de cámara. Contraste, escalado de texto, foco, lector de pantalla y tamaños táctiles deben comprobarse sobre las interfaces y dispositivos correspondientes. No se deducen fuentes exactas, medidas, contraste medido ni cumplimiento de accesibilidad a partir de una imagen.

El desarrollo de diseño y sus estados se interpreta conforme a la [separación entre evidencia, verificación y aceptación](https://github.com/nexa-suite/blueprint/blob/d5bc761f8877ed30d7464573825e3f02b084f914/01-shared/engineering/governance/source-of-truth.md). La fidelidad visual de una captura no equivale a Product/UX Acceptance, System Acceptance ni Production Readiness.
