#### 3.1.4.3 Mock-ups de aplicaciones Mobile

Los mock-ups deberán expresar la dirección de Design Lab sin alterar los
límites de dominio. Se requiere, como mínimo, un estado de sesión y contexto,
un flujo de Operations, un estado de Delivery o POD y un estado de Buyer
Receipt o Discrepancy para las superficies seleccionadas.

| Superficie | Composición que debe representar | Límite de esta entrega |
| :--- | :--- | :--- |
| Operations Mobile | Estados de almacén, despacho y entrega; objetivos táctiles, error y reintento | No se adjunta un mock-up visual |
| Buyer Mobile | Verificación de transferencia, cantidades, recepción y discrepancia | No se adjunta un mock-up visual |
| Adaptación y accesibilidad | Foco, contraste, espaciado de texto, movimiento reducido y comportamiento a 320/390 px | No se declara una revisión realizada |

Un mock-up futuro deberá identificar la historia, vista, estado de interacción
y referencia de diseño que representa. Por sí solo, no demuestra autorización,
persistencia, seguridad de reintentos ni aceptación de producto.
