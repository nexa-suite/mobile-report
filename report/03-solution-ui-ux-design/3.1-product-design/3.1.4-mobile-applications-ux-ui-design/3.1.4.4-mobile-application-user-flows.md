#### 3.1.4.4 Flujos de usuario de aplicaciones Mobile

##### Especificación textual de flujos

```text
Trabajo autorizado:
retorno → comprobación de sesión/contexto → capacidad permitida → trabajo asignado
  ├─ expirado/revocado → recuperación de identidad/contexto → sin datos protegidos
  └─ no disponible → estado seguro → reintento sin comando

Transferencia de entrega:
trabajo preparado → Dispatch Handoff → Delivery asignada → intento/resultado
  ├─ parcial/rechazado → conservar cantidades/motivo → continuación autorizada
  └─ evidencia pendiente → evidencia no resuelta → reintento sin cierre falso

Recepción del comprador:
actualización → verificar código de transferencia → confirmar cantidades
  ├─ coincide → Buyer Receipt
  ├─ diferencia → Buyer Receipt + Discrepancy
  └─ inválido/no disponible → sin confirmación de recepción → recuperación segura
```

Esta especificación conserva la trazabilidad de los caminos principales y de
recuperación. No sustituye un diagrama visual ni prueba comportamiento en una
aplicación; Driver Outcome, Buyer Receipt, Proof of Delivery, Notification,
Payment y Business Traceability deben seguir tratándose como hechos o estados
distintos.
