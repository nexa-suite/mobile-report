# 3.1.4.4 Mobile Applications User Flow Diagrams

## Textual flow register

```text
Authorized work:
return → session/context check → permitted capability → assigned work
  ├─ expired/revoked → identity/context recovery → no protected data
  └─ unavailable → safe unavailable state → retry without command

Delivery handoff:
prepared work → Dispatch Handoff → assigned Delivery → attempt/outcome
  ├─ partial/rejected → preserve quantities/reason → continuation if authorized
  └─ proof pending → unresolved evidence → retry without false completion

Buyer receipt:
attention update → verify handoff code → confirm quantities
  ├─ match → Buyer Receipt
  ├─ difference → Buyer Receipt + Discrepancy
  └─ invalid/unavailable → no receipt confirmation → recover safely
```

The textual register provides traceability while a diagram is pending. Happy
and unhappy paths must keep Driver outcome, Buyer Receipt, Proof of Delivery,
Notification, Payment and Business Traceability as separate facts/states.
