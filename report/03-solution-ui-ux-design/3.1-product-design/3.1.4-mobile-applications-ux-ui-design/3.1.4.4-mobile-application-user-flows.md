#### 3.1.4.4 Mobile Applications User Flow Diagrams

Los user flows relacionan las metas de las personas con sus decisiones, pantallas y resultados. Las láminas de esta sección usan capturas de alta fidelidad; sus homólogas de baja fidelidad se presentan en 3.1.4.2. Ambas familias conservan el mismo identificador y el mismo límite funcional. Un estado de error o una nota de falta de cobertura no se transforma en una operación completada.

**Desarrollo de diseño en Figma.** [Nexa Mobile — archivo de diseño](https://www.figma.com/design/6V8PMiotchS4rY9tX97JtF/Nexa-Mobile?node-id=33-2&t=KIE195t7KUVTUMNw-1). La referencia de esta sección es la página **User Flows — Prototype** del archivo.

Las exportaciones muestran secuencias visuales sin conectores visibles. La lectura por objetivo y las decisiones descritas a continuación complementan esas láminas. No se infiere una secuencia de eventos del servidor únicamente por la posición de las capturas. Las escenas de reintento rotuladas como reportadas no constituyen una comprobación independiente.

**Decisión y recuperación.** La decisión es usar búsqueda manual o cámara. Ante una lectura no disponible, se mantiene la alternativa manual. Un resultado vacío permite corregir el criterio; una coincidencia requiere revisar el SKU. Las escenas diagnósticas no se convierten en el camino normal.

##### BY-11 — Consultar entrega y declarar recepción o diferencia

*Figura 3.1.4.4-10. BY-11: vistas de alta fidelidad y alcance del objetivo.*

**Recorrido visual disponible.** Tus compras, Pedidos, pestaña Solicitudes y pestaña Seguimiento con indisponibilidad. No se muestra una entrega concreta ni un recibo.

##### Correspondencia entre conductor y comprador

OP-12 y BY-11 expresan tareas de personas distintas. En el diseño esperado, el conductor presenta un código de Delivery/Attempt; el comprador lo verifica con su Buyer Relationship y declara después las cantidades recibidas o una diferencia. **La verificación identifica el handoff; no es recepción, POD ni finalización.** El resultado del conductor, el POD y el Buyer Receipt permanecen separados y las discrepancias conservan los hechos originales.
