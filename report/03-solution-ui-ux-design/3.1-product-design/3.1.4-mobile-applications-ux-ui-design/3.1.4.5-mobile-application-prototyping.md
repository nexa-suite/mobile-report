#### 3.1.4.5. Prototipado de aplicaciones Mobile

##### Alcance de prototipado

No se incorpora un prototipo interactivo, capturas de interacción ni evidencia
de dispositivo físico en esta entrega. La siguiente delimitación indica qué
material sería necesario antes de afirmar que esos resultados existen.

*Evidencia requerida para el futuro prototipado de aplicaciones Mobile.*

| Evidencia | Contenido necesario |
| :--- | :--- |
| Prototipo de Operations Mobile | Enlace de revisión, versión, estados de pantalla y trazabilidad de historias |
| Prototipo de Buyer Mobile | Enlace de revisión, estados de transferencia, recepción y discrepancia |
| Captura de interacción | Imagen o video con vista, fecha y referencia de diseño |
| Revisión de accesibilidad | Equivalente de teclado o foco cuando corresponda, contraste, reflujo y notas de tecnología asistiva |
| Revisión en dispositivo | Dispositivo Android físico, paquete o build y resultado observado |

*Nota.* Estos son requisitos de evidencia para el hito futuro; la tabla no
afirma que un prototipo, captura o prueba en dispositivo exista actualmente.

Un frame de Figma o una captura estática no prueban autorización de API,
persistencia, seguridad de reintentos ni aceptación de producto. El proceso de
prototipado debe hacer visibles alternativas y decisiones de diseño conforme a
la evidencia orientada al proceso descrita por Ilhan (2025); el producto Nexa requiere
evidencia propia de usuario, historia y dispositivo para sostener tales
afirmaciones.

Cuando exista un artefacto evaluable, la preparación de una evaluación de
usabilidad podrá contrastar atributos de calidad de aplicaciones móviles
sintetizados por Weichbroth (2024). Esa referencia orienta el diseño del
instrumento, pero no sustituye sesiones ni resultados propios.

El prototipo futuro se construirá en Figma a partir de los user flows y deberá
aportar sus enlaces, estados y capturas de interacción como evidencia fechada.
Hasta entonces, el prototipado y la revisión en dispositivo conservan el estado
**NOT YET DUE** definido al inicio del capítulo.
