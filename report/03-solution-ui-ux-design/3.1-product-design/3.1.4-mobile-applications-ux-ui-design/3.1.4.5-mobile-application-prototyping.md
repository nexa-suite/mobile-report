# 3.1.4.5 Mobile Applications Prototyping

## Prototype evidence register

| Artifact | Required evidence | State |
| :--- | :--- | :--- |
| Operations Mobile prototype | Public/review link, version, screen states, story mapping and reviewer | Not produced |
| Buyer Mobile prototype | Public/review link, handoff/receipt/discrepancy states and reviewer | Not produced |
| Interaction capture | Screenshots or video with viewport, date and source revision | Not produced |
| Accessibility review | Keyboard/focus equivalent where applicable, contrast, reflow and assistive-technology notes | Not produced |
| Device review | Physical Android device, build/package and observed result | Not produced |

Prototype completion requires a human reviewer to exercise both happy and
unhappy paths. A Figma frame or static screenshot alone does not prove API
authorization, persistence, retry safety or Product Acceptance.

The prototyping process should make design alternatives and decisions visible,
following the process-oriented evidence described in [M1]. The citation is
methodological guidance only; the Nexa prototype still requires its own user,
story and device evidence.
