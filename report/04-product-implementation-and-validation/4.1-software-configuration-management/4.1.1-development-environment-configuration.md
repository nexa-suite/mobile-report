# Capítulo IV: Product Implementation & Validation

## 4.1. Software Configuration Management

### 4.1.1. Software Development Environment Configuration

La configuración reúne herramientas para planificación, requisitos, UX/UI,
desarrollo, pruebas, despliegue, documentación y control de versiones. Las
herramientas previstas para clientes Mobile se distinguen de una evidencia de
build, instalación o uso en dispositivo.

El Board de Jira conserva un estado de planificación observado y debe
reconciliarse con el alcance académico de Sprint 2. Los Personas, Journey Maps
y Empathy Maps incorporados al informe fueron elaborados en UXPressia y
exportados como artefactos de investigación; no constituyen evidencia de un
prototipo ni de validación. Operations Mobile tiene una implementación Android
activa con Kotlin y Jetpack Compose; Buyer Mobile permanece como un track
separado y no se declara implementado en este corte.

El alcance técnico distingue Operations Android, implementado con Kotlin y
Jetpack Compose, de Buyer Mobile, cuyo objetivo aceptado conserva Flutter 3.47.x
y Dart 3.13.x como un track separado que no se declara implementado en este
corte. Kotlin Multiplatform (KMP) queda como alternativa evaluada en la
proveniencia histórica, no como una selección vigente. Operations Android se
verificó con Kotlin 2.4.x, Compose, AGP 9.4.x, JDK 17, SDK 37 y mínimo API 29.
El wrapper observado usa Gradle 9.7.1, mientras que el baseline aceptado del
proyecto registra Gradle 9.6.x; esa diferencia queda documentada como una
variación que debe resolverse por la autoridad técnica.
