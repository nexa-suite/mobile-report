# Capítulo IV: Product Implementation & Validation

## 4.1. Software Configuration Management

### 4.1.1. Software Development Environment Configuration

La configuración reúne herramientas para planificación, requisitos, UX/UI,
desarrollo, pruebas, despliegue, documentación y control de versiones. Las
herramientas previstas para clientes Mobile se distinguen de una evidencia de
build, instalación o uso en dispositivo.

El Board de Jira permanece **OPEN**. Los Personas, Journey Maps y Empathy Maps
incorporados al informe fueron elaborados en UXPressia y exportados como
artefactos de investigación; no constituyen evidencia de un prototipo ni de
validación. La decisión de framework Mobile sigue **OPEN / NOT STARTED**; las
alternativas académicas de cliente sólo pueden evaluarse como experimentos
acotados.

La obligación académica se lee inequívocamente como **Kotlin Android AND
(Flutter/Dart OR KMP/Kotlin)**: el Track A obligatorio es Android nativo con
Kotlin y el Track B obligatorio es una alternativa multiplataforma, Flutter con
Dart o Kotlin Multiplatform (KMP) con Kotlin. Esta declaración de requisito no
selecciona framework ni demuestra implementación.
