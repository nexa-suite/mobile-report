## GitFlow baseline

| Branch class | Purpose | Rule |
| :--- | :--- | :--- |
| `main` | Stable/releasable report | Actual release only |
| `develop` | Integration | Feature branches merge through review |
| `chapter-01` … `chapter-04` | Academic chapter lines already present in the repository | Do not rewrite history |
| `feature/<scope>-<feature>` | Short-lived related work | Create from `develop` or the explicitly reviewed base |
| `release/v<major>.<minor>.<patch>` | Actual release preparation | Tag only after merge to `main` |

## Traceable change rules

- Use one logical, reviewable change per Conventional Commit.
- Use English, lowercase type/scope and an imperative concise subject.
- Do not use co-authorship trailers or persist another person's identity.
- Verify the owner, GitHub username and email association with that person
  before a commit checkpoint.
- Preserve source SHA, file list, validation and owner explanation in the Human
  Commit Gate.
