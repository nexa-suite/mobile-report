### 4.1.3. Source Code Style Guide & Conventions

Todos los identificadores de código, contratos de API, nombres de archivo y
términos de dominio usan inglés. El texto visible para personas usuarias puede
localizarse mediante la estrategia i18n del producto.

*Convenciones de nomenclatura y código aplicables por lenguaje o formato.*

| Lenguaje / formato | Convención de nomenclatura y código | Referencia |
| --- | --- | --- |
| HTML | Semantic elements, one meaningful landmark structure, perceptible labels and valid document language. | [WHATWG HTML](https://html.spec.whatwg.org/) |
| CSS | Token-based values, component-scoped naming, responsive layout and no color-only meaning. | [W3C CSS](https://www.w3.org/TR/CSS/) |
| JavaScript | camelCase variables and functions, PascalCase classes, explicit error handling and no business authorization in browser code. | [MDN JavaScript Guide](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide) |
| Java | PascalCase types, camelCase members, package names in lowercase, explicit boundaries and tests for business behavior. | [Oracle Java](https://www.oracle.com/java/) |
| Kotlin | PascalCase types, camelCase functions and properties, immutable values by default, explicit UI states and official formatting. | [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html) |
| Dart | PascalCase types, lowerCamelCase members, null-safe models and linted formatting. | [Effective Dart](https://dart.dev/effective-dart/style) |
| Gherkin | Feature, Scenario, Given, When and Then express observable behavior, constraints and recovery paths. | [Cucumber Gherkin](https://cucumber.io/docs/gherkin/reference/) |
| Markdown | Semantic heading depth, relative links, accessible alt text and tables used only for structured comparison. | [CommonMark](https://spec.commonmark.org/) |

*Nota.* Estas convenciones guían el código y la documentación futuros; no
prueban una implementación de los tracks Mobile.
