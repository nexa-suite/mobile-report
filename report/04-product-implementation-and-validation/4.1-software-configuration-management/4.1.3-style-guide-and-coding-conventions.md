# 4.1.3 Source Code Style Guide and Coding Conventions

## Shared conventions

- Domain terms, classes, functions, identifiers, API fields and database
  objects use the accepted English vocabulary; user-facing text may be
  localized.
- Names reflect the owning Bounded Context and do not create technical
  contexts such as Mobile, Scanner, QR, Offline or Tracking.
- Commands, retries and external callbacks require explicit idempotency and
  unknown-result handling.
- Persistence names preserve tenant/workspace scope and logical ownership.
- Tests describe business behavior and failure states; a green build is not
  Product Acceptance.
- Accessibility semantics, visible labels and localization keys are part of a
  UI change, not optional polish.

## Evidence status

Estas son reglas del informe alineadas con el modelo de dominio y arquitectura
adoptados. El informe actual no contiene un árbol fuente Mobile cuya adherencia
pueda verificarse. La versión final debe citar el repositorio del cliente
seleccionado, formatter/linter, comando de pruebas y salida de revisión.
