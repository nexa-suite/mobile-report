### 4.1.3. Source Code Style Guide & Conventions

Los identificadores de código, contratos y términos de dominio se mantienen en
inglés; el contenido destinado a usuarios puede localizarse. Las convenciones
aplicables por tecnología son las siguientes.

| Tecnología o formato | Convención principal |
| :--- | :--- |
| Kotlin | Separar presentación, aplicación y contratos; representar estados de error y resultado incierto de forma explícita |
| Dart | Mantener la misma autoridad de contratos y no duplicar reglas de negocio del servidor |
| Java | Preservar límites de contexto, validación de tenant/workspace e idempotencia en comandos sensibles |
| HTML, CSS y JavaScript | Usar estructura semántica, etiquetas perceptibles y composición responsive sin delegar autorización al navegador |
| Gherkin | Describir comportamiento y recuperación mediante escenarios legibles, no sólo rutas felices |
| Markdown | Usar jerarquía de encabezados, enlaces verificables y límites explícitos de evidencia |

Una convención es un criterio de construcción, no una prueba de que exista un
árbol fuente Mobile adherente. Las verificaciones de formatter, linter, build o
tests deben citarse únicamente cuando se hayan ejecutado sobre el artefacto
correspondiente.
