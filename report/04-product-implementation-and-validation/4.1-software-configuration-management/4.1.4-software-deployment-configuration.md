### 4.1.4. Software Deployment Configuration

La publicación del Website, el despliegue de Nexa API y la
distribución de las aplicaciones móviles se realizan mediante
procesos independientes. El Website se publica como un sitio
estático, mientras que el API se ejecuta en un entorno de
servidor y proporciona los servicios que utilizan las
aplicaciones móviles. Esta organización permite mantener
separadas las configuraciones de despliegue y preservar
la responsabilidad del servidor sobre la autorización y
las operaciones de negocio.

**Implementación y distribución de Buyer Mobile**

Buyer Mobile cuenta con una implementación desarrollada en
Flutter y Dart, orientada a facilitar las actividades de los
compradores empresariales. Su código fuente se encuentra en
el [repositorio Nexa Mobile](https://github.com/nexa-suite/mobile/tree/main/apps/buyer-mobile),
que también dispone de publicaciones de versiones y
artefactos académicos para Android.

La aplicación incorpora funcionalidades relacionadas con
la consulta de productos, información de la cuenta, pedidos,
pagos y seguimiento de entregas. No obstante, la integración
con los servicios publicados todavía presenta limitaciones,
especialmente en los procesos comerciales y de entrega.

Es importante distinguir la implementación de la aplicación
de su disponibilidad funcional. La existencia del código
fuente y de un artefacto instalable no demuestra que todos
los procesos estén habilitados ni que el producto haya
completado sus pruebas de aceptación.

El Dockerfile del API compila con Maven sobre Eclipse Temurin 25 y ejecuta el
JAR en una imagen Eclipse Temurin 25 JRE. El proceso del contenedor usa un
usuario sin privilegios, escucha en el puerto 8080 y dispone de un chequeo de
salud de contenedor. Render construye desde la rama `main`; el último despliegue
que presenta el dashboard fue manual y apunta al commit `78a3060`. La release
API [v1.0.0](https://github.com/nexa-suite/api/releases/tag/v1.0.0) es una
publicación de fuente basada en el corte compatible v0.21.0. El registro de
Render identifica el commit desplegado en `main`, no una promoción directa de
la etiqueta v1.0.0.

El Website es estático y no comparte el rol de servidor del API. Operations
Mobile usa el origen HTTPS para solicitar operaciones autorizadas; la interfaz
no concede permisos ni cambia por sí sola el estado de negocio. La
configuración de base de datos y correo se describe desde el manifiesto y el
recorte de configuración visibles, sin reproducir secretos o valores de
entorno.
