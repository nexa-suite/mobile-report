### 4.1.4. Software Deployment Configuration

La configuración de despliegue preserva la separación entre Landing Page,
servicios y aplicaciones Mobile. Cada producto requiere un artefacto
identificable, configuración sin secretos y evidencia de resultado antes de
declarar su publicación. Este corte distingue la publicación pública observada
del estado técnico pendiente de los servicios y de la aplicación móvil.

*Configuración y evidencia requeridas antes de declarar un despliegue.*

| Product | Source-to-deployment configuration | Evidence required |
| --- | --- | --- |
| Landing Page | Construir contenido estático desde el repositorio Website, configurar host, dominio, metadatos, enlaces legales y rollback. | La fuente pública `main` del Website es `300232c0c2b86e43cee4f54015bdf55498864751`; GitHub Pages figura como `built` y las páginas representativas respondieron HTTP 200. Aún se requiere completar la evidencia de presentación, contacto y revisión responsive solicitada por la rúbrica. |
| Web Services | Construir desde API, aplicar migraciones, configurar PostgreSQL, Object Storage, secretos, OpenAPI, observabilidad y rollback. | `main` permanece en `7294def5974ba24fe49649f8c2d9810dfa789984` y la propuesta de corrección de despliegue continúa abierta. La aplicación de migraciones en Neon alcanzó la versión 144 sin pendientes ni fallos y el verificador de ejecución confirmó las restricciones de permisos. El resultado público de Render sigue sin verificarse; no se declara despliegue exitoso. |
| Operations Mobile | Generar build identificable, configurar endpoint, permisos, firma y canal de distribución. | La rama integrada `develop` se observó en `6f51a370f30c791e288ae6970b30bf3d173f8c70`; existen pruebas automatizadas y un smoke de instalación e inicio en Samsung SM-S908E API 36, pero no un recorrido autenticado completo ni una distribución pública. |
| Buyer Mobile | Generar build identificable, configurar endpoint, permisos, firma y canal de distribución. | No se dispone en este corte de un build ni de una validación de Buyer Mobile que permita declarar publicación. |

*Nota.* La tabla conserva los requisitos de despliegue y actualiza el estado con
fuentes públicas y registros técnicos fechados. Una URL accesible, una prueba
automatizada o una configuración guardada no equivale por sí sola a aceptación
del producto ni a disponibilidad de producción.

El Deployment Diagram del Capítulo II explica la relación entre estas
superficies. Una rama, una configuración de entorno o un enlace de prototipo no
equivale por sí solo a despliegue.
