## Required deployment record

Antes de llamar completo a un deployment, registra SHA de origen, comando de
build, checksum del artefacto, contrato de configuración, manejo de secretos,
versiones de servicios, estado de migraciones, URL o canal de distribución,
dispositivo de instalación, resultado observado y ruta de rollback. No
committees secretos ni trates una instalación Docker local como preparación
cloud.

El objetivo de deployment C4 y sus límites se describen en
[2.5.3.4 Deployment Diagrams](../../02-requirements-and-software-solution-design/2.5-strategic-level-domain-driven-design/2.5.3-software-architecture/2.5.3.4-deployment-diagrams.md).

La observación local se documenta en la
[live baseline](../../../delivery-checklists/live-baseline.md) and the
[implementation evidence register](../../../delivery-checklists/implementation-evidence-register.md).
Es sólo un entorno local de validación: no establece deployment cloud,
distribución, instalación en dispositivo físico ni preparación para producción.

## Reproducible report export

Ejecuta scripts/export-report-pdf.sh /absolute/path/report.pdf desde el
repositorio del informe. La ruta predeterminada es un archivo temporal. Docker
usa la imagen pandoc/latex fijada en el script y emulación linux/amd64 en el
host Apple Silicon. El filtro de exportación ajusta las tablas Markdown y
traduce símbolos exclusivos del export sin cambiar el origen académico. El PDF
generado todavía debe recibir revisión visual humana antes de nombrarse como
artefacto de entrega AV1, TB1, AV2 o TB2.
