#### 4.2.1.7. Services Documentation Evidence for Sprint Review

Los contratos se verificaron read-only en `nexa-suite/api`. El contrato estático
se conserva en [docs/openapi](https://github.com/nexa-suite/api/tree/develop/docs/openapi)
y fue revisado en `a2f062fdc94844a31d8b49415ba4de7cb009fef9`; con el perfil
local, la documentación se expone en `http://localhost:8080/v3/api-docs`. El
servidor conserva autoridad sobre identidad, sesión, Tenant, Workspace,
permisos y resolución SKU.

*Contratos de servicio relacionados con Sprint 1*

| Método y ruta | Parámetros / body observado | Respuesta y significado | Relación con Sprint 1 |
| --- | --- | --- | --- |
| `POST /api/v1/authentication/sign-in` | `identifier`, `password`, `workspaceSlug`, `surface`; cliente nativo con `ClientSurface.PLATFORM` y `X-Nexa-Client: NATIVE`. | HTTP 200 con access token, expiración y sesión. | `MOB-US-001`; `TS-MOB-001` |
| `POST /api/v1/authentication/refresh` | Refresh token y marker de superficie. | HTTP 200 con header refresh de reemplazo; un refresh fallido invalida la sesión local. | `MOB-US-001`; `TS-MOB-001` |
| `POST /api/v1/authentication/sign-out` | Bearer y superficie; sin body. | HTTP 204 para cierre de sesión. | `MOB-US-001`; `TS-MOB-001` |
| `GET /api/v1/session` | Bearer de sesión vigente. | HTTP 200 con usuario, Tenant, Workspace, membership y surface confirmados por servidor. | `MOB-US-002`, `MOB-US-003`; `TS-MOB-001` |
| `GET /api/v1/skus/resolve?identifier=<value>` | Query `identifier`, bearer y visibilidad Tenant/Workspace. | Conserva `RESOLVED`, `NOT_FOUND` o `AMBIGUOUS`; una respuesta ambigua no selecciona `skuId`. | `MOB-US-011`; `TS-MOB-007` |
