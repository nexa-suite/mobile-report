# Glosario

| Término | Definición en este informe |
| :--- | :--- |
| Tenant | Límite máximo de datos y seguridad para una organización de Nexa. |
| Workspace | Entorno operativo asociado uno a uno con un Tenant en el alcance académico actual; no reemplaza autorización ni es un contenedor C4. |
| Human Identity | Identidad de una persona usada para autenticación y atribución. |
| Workforce Membership | Relación de autorización entre una Human Identity, un Workspace y capacidades permitidas. |
| Customer Account | Organización comercial representada en Nexa. |
| Buyer Relationship | Relación autorizada entre un Customer Account o persona y la operación comercial de un Tenant. |
| Product / SKU | Identidad de catálogo que distingue un producto vendible u operativo de su unidad de mantenimiento. |
| Commercial Commitment | Promesa comercial u orden; no equivale a una asignación física de inventario. |
| Inventory Reservation | Protección de inventario disponible para un compromiso autorizado. |
| Physical Allocation | Asignación de stock, lote o cantidad física a trabajo operativo. |
| Safety Stock | Umbral de política de inventario que protege disponibilidad; no es una cantidad disponible por sí mismo. |
| Dispatch Handoff | Transferencia explícita de trabajo preparado desde despacho hacia la ejecución de entrega. |
| Delivery Attempt | Intento atribuible de ejecutar una entrega. |
| Delivery Outcome | Registro de lo ocurrido físicamente en un destino. |
| Buyer Receipt | Registro del comprador sobre las cantidades realmente recibidas. |
| Proof of Delivery | Evidencia asociada a un Delivery Outcome autorizado. |
| Discrepancy | Diferencia reportada entre hechos de entrega o recepción sin borrar los hechos originales. |
| Payment Reported | Afirmación de pago recibida desde una persona o proceso externo. |
| Payment Confirmed | Estado de pago confirmado por el flujo de pagos autorizado. |
| Business Traceability | Representación durable de hechos de negocio confirmados entre contextos. |
| Lean UX | Enfoque que conecta problemática, supuestos, hipótesis y aprendizaje mediante experimentos. |
| User Persona | Arquetipo de investigación utilizado para formular preguntas de diseño; no es una identidad real ni un rol de autorización. |
| C4 | Modelo de visualización de arquitectura para contexto, contenedores, componentes y despliegue. |
| CRUD | Create, Read, Update and Delete; no sustituye invariantes de dominio ni límites de casos de uso. |
