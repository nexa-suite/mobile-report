# Glosario

El vocabulario de negocio utilizado en Nexa se desarrolla en la sección 2.3.6,
Ubiquitous Language. Este glosario complementa esa referencia con abreviaturas
y conceptos de investigación, diseño e ingeniería empleados en el informe.

*Abreviaturas y conceptos para la lectura del informe.*

| Término | Significado en el informe |
| --- | --- |
| API (Application Programming Interface) | Interfaz mediante la cual las aplicaciones solicitan y consultan operaciones de los servicios. |
| APK (Android Package) | Archivo de distribución utilizado para instalar una aplicación Android. |
| AV1 / TB1 | Entregas acumulativas del proyecto: AV1 conserva la evidencia de Sprint 1 y TB1 incorpora Sprint 2. |
| B2B (Business-to-Business) | Relación comercial entre empresas. |
| BA / BOA | Business Assumption y Business Outcome Assumption: supuestos de negocio y de resultados de negocio formulados en Lean UX. |
| UA / UOBA / FA | User Assumption, User Outcome & Benefit Assumption y Feature Assumption: supuestos sobre usuarios, beneficios y características de la solución. |
| C4 | Forma de representar la arquitectura mediante vistas de contexto, contenedores, componentes y código con distintos niveles de detalle. |
| CI (Continuous Integration) | Ejecución automatizada de comprobaciones asociadas a cambios del repositorio. Un resultado satisfactorio se refiere a las comprobaciones ejecutadas. |
| DDD (Domain-Driven Design) | Enfoque de diseño que relaciona el conocimiento del negocio con modelos y responsabilidades del software. |
| GitFlow | Organización del trabajo con ramas de desarrollo, funcionalidades y publicaciones; conserva la separación entre integración y versiones publicadas. |
| Happy Path / Unhappy Path | Secuencia esperada para lograr una tarea y alternativa ante una excepción o impedimento, respectivamente. |
| HTTPS | Comunicación HTTP protegida mediante TLS. |
| Impact Mapping | Relación entre un objetivo, actores, cambios de comportamiento y entregables propuestos. |
| JWT (JSON Web Token) | Formato de token utilizado para transmitir declaraciones de identidad y acceso que el servicio debe validar. |
| Lean UX | Enfoque de aprendizaje mediante supuestos, hipótesis y experimentos sobre resultados de la experiencia de usuario. |
| Material 3 | Sistema de diseño utilizado como referencia para jerarquía, componentes, interacción y presentación de la aplicación Android. |
| Mock-up | Representación visual de la apariencia de una interfaz; su existencia no demuestra que esa interfaz esté implementada. |
| Needfinding | Investigación de necesidades, tareas y dificultades de los usuarios. |
| OpenAPI / Swagger UI | Especificación de los contratos HTTP y herramienta para explorarlos, respectivamente. La documentación de una operación no acredita por sí sola su funcionamiento. |
| PBI (Product Backlog Item) | Elemento del Product Backlog, como una historia funcional, una Technical Story o un Spike. |
| PoC (Proof of Concept) | Prueba acotada para explorar la viabilidad de una alternativa técnica. |
| PR (Pull Request) | Solicitud de revisión e integración de cambios en un repositorio. |
| Release | Publicación de una versión identificada del software o del informe. |
| SCM (Software Configuration Management) | Gestión de versiones, configuración y trazabilidad de los artefactos del proyecto. |
| SMTP | Protocolo utilizado para enviar correo electrónico. |
| SP (Story Points) | Estimación relativa de un elemento del backlog; no representa horas trabajadas. |
| Sprint Backlog | Trabajo seleccionado y organizado para el Sprint, junto con su seguimiento. |
| Original Estimate / Time Spent | Estimación de esfuerzo registrada en Jira y tiempo efectivamente registrado, respectivamente. Son datos distintos. |
| UI / UX | Interfaz de usuario y experiencia de usuario. |
| User Flow / Wireflow | Recorrido orientado a un objetivo del usuario y representación de la secuencia entre pantallas, respectivamente. |
| Wireframe | Representación de la estructura y distribución de una interfaz. |
